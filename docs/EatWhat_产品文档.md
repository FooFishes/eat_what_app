本文描述「沙软今天吃什么」的最终形态：为谁做、解决什么问题、每个功能具体怎么表现。它是开发的依据，回答「做成什么样」。

- 行为和规则以本文为准。

## 1. 产品是什么

**一句话**：沙软今天吃什么，帮山东大学软件园校区的同学在饭点一下子定下吃什么，再把吃到的好菜分享给同学。

**要解决的问题**

1. 饭点选择困难。软件园周边的店不少，但每天能想起来的就那几家。打开外卖或点评 App，面对的是几百家店、满屏满减和广告，越刷越定不下来。
2. 好吃的信息散在宿舍群和口口相传里。新生不知道西门小吃街哪家好，老生吃到好菜也没地方留下来。食堂窗口这类店，外部平台几乎没有收录。

**我们的回答**

- 一次给一家店：店名、招牌菜和价格、多远、多少人推荐。不满意就「换一个」，满意就「就它了」
- 招牌菜是店的脸。同学之间分享的仍是具体的菜，一道菜是店铺菜单里的一项
- 内容来自同校同学的实拍、评价和评论，不接商家，不做广告

## 2. 为谁做

### 2.1 用户

| 用户                                     | 他们要什么                       | 主要用到                 |
| ---------------------------------------- | -------------------------------- | ------------------------ |
| 软件园在读学生（主要用户）               | 饭点前几分钟定下吃什么，不想多想 | 发现、菜品详情、导航     |
| 爱吃、爱分享的同学                       | 把好菜留下来，被人看到、被人赞   | 发布、评论、我的、消息   |
| 刚到软件园的同学（新生、换校区的研究生） | 摸清周边有哪些店、哪些值得去     | 附近、餐厅详情           |
| 校外或还没认证的人                       | 看看软件园的同学都在吃什么       | 只能浏览，不能发布和互动 |

只面向山大在读学生。最先开放软件园校区，之后按校区逐个开放（见 4.1）。

### 2.2 典型场景

**饭点纠结**。11:50 下课，打开 App 落在发现页。舞台上是「袁记云饺」，盘子里是它的招牌鲜虾蟹籽云吞，「¥18，320 m，86% 推荐」。不太想吃，左滑换到下一家，再点「换一个」到「柳州螺蛳粉」。就它了，进餐厅详情看一眼招牌菜和评价，点「导航去店里」打开地图。

**和室友约饭**。在菜品详情点分享，发到宿舍群。室友点开链接，装了 App 的直接进这道菜，没装的打开一个轻量的分享页面。

**吃到好吃的**。吃完拍一张，点导航栏右边的「＋」。选店（离你近的排在前面），加照片，把菜拖进圆圈，选一个舞台色，填菜名和价格。分类和口味已经按照片预选好，改一个口味，发布。

**已经有人发过**。想发的菜别人已经发过了。输完菜名，App 提示「这家店已有鲜虾蟹籽云吞」，带他去那道菜，刚拍的照片已经放进评论框，他补一句「加了辣油更好吃」发出去。

**刚到软件园**。打开附近，地图上是周边的店。切到「西门小吃街」，筛一下「¥15 以下」，沿着列表一家家看，进店看招牌菜、口味和推荐率。

**收到反馈**。手机上弹出「小林收藏了你上传的鲜虾蟹籽云吞」。打开 App，消息里还有「阿哲回复了你：同意，加辣更好」，有人关注了你，顺手回关。

## 3. 产品原则

做取舍时按这几条来，排在前面的优先。

1. **帮人定下来，而不是让人挑**。发现页的主角永远是一家具体的店，用它的招牌菜当脸，交互围绕「换一个」和「就它了」。列表、筛选、排序都是配角。
2. **推荐落在店上，分享落在菜上**。推荐和店铺评价的单位是店；同学之间分享的是具体的菜，菜是店铺菜单里的一项，赞、收藏、评论落在菜上。
3. **真实优先**。舞台上只放用户实拍，插画只用于空状态、引导和演示。不接商家投放，推荐位不卖。
4. **少打字**。口味从几个固定的词里点选；菜用赞和 1–5 分，店用「推荐」「不推荐」，都不打星。发布控制在两步，必填项尽量少，能预选的先预选。
5. **不藏功能**。做不了的事也让人看见，并告诉他怎么才能做。比如没认证时点赞，告诉他去认证，而不是把按钮藏起来。
6. **引导亲切，提示规范**。文案短、直接：引导像同学之间说话，提示和报错用规范短句。用词按设计规范「内容与语气」。

## 4. 核心概念

### 4.1 地点：校区和商圈

- **校区**是「在哪吃」，决定推荐、附近和专题的范围。首页左上角显示当前校区，点开可以切换。开放哪些校区由运营决定，最先开放软件园。
- 默认「按定位」：按当前定位选离你最近的已开放校区，没有定位就选软件园（默认校区）。手动选了校区就一直用它，直到切回「按定位」。
- **商圈**是校区周边一片店铺聚集的区域，有地理边界，比如「万达金街」「银座商城」「校内食堂」「西门小吃街」。一个校区包含若干商圈。
- 一家店按位置归入一个商圈，也可以不属于任何商圈。
- 食堂也是商圈，食堂里的每个窗口算一家店，比如「二餐 2 楼麻辣烫」。

### 4.2 店

- 一家店有：店名、位置、地址描述（「万达金街 1 层」「B1」）、所属商圈、类型、品类、口味、饭点、价位、能不能点外卖（由菜汇总）、门头照片（选填）。
- 店由认证用户在发布流程里新建。店的信息从地图上的地点来，让同一家店不会出现不同的信息；地图上搜不到的店手动添加。附近已有同名的店、或者同一个地点已经有店时会提示，避免建重复（见 9.2）。
- **类型**：「美食」「甜点饮品」或「自助」，必选。能吃饱的都算美食，炸串、麻辣烫、煎饼、烧烤摊都是；奶茶、甜品、咖啡是甜点饮品；自助餐是自助。推荐和附近按类型分开看。
- **品类**：米饭炒菜、粉面、火锅麻辣烫、烧烤炸串、汤粥、面点快餐、日韩料理，最多 2 个，选填。用于筛选和推荐，也决定店的默认舞台色（4.7）。
- **口味**：辣、麻、甜、酸、清淡，最多 3 个，选填。是这家店自己的属性，和菜的口味（4.3）用同一组词。
- **饭点**：这家店做哪几顿（早饭、午饭、晚饭、夜宵），新建时默认午饭、晚饭。菜可以单独选饭点，不选就跟店一样（4.5）。早饭、夜宵时段只推荐带这个饭点的店（第 8 节）。
- **价位**：「¥15 以下」「¥15–30」「¥30 以上」三档，是店铺自己的字段，由编辑者选，可以不填。用于附近的筛选。
- **能点外卖**：不在店上填。能不能点外卖在菜上设（4.3），店里有能点外卖的菜，这家店就算能点外卖。能点外卖，或者有人评过外卖，这家店才进外卖的推荐。
- **招牌菜**：编辑者在菜上标记，每家店最多 3 道。招牌菜是店的脸：发现页的盘子、店的封面、地图标记用第一道招牌菜的封面；没有招牌菜时用门头照，都没有时是 `mist` 底。
- **店铺评价**：吃过的同学按「堂食」「外卖」两个场景，各选「推荐」或「不推荐」，对外显示推荐率（见 9.7）。菜不打这个评价，菜用赞，另外可以打 1–5 分。
- **状态**：正常或已关门。编辑者把店标为已关门后：不再出现在推荐、附近和选店里，搜索还能搜到，餐厅详情写明「这家店已关门」。
- **编辑**：认证用户都能编辑店铺资料，每次修改留一条修改记录，所有人都能看，可以恢复到某个版本（9.4）。只有管理员能删除店铺。拿不准的问题仍可以点「信息有误」告诉我们。

### 4.3 菜

- 一道菜是一家店菜单里的一项，有：菜名、价格、分类、照片（第一张是封面，上限由服务端定，目前 9 张）、封面的圆形裁切和舞台色、说明（最多 200 字）、口味、饭点、能不能点外卖、是不是招牌菜、评分、评论。
- **口味**是菜自身的属性：辣、麻、甜、酸、清淡，最多 3 个，和店的口味用同一组词。由发布和编辑的人选，所有人看到的一样。
- **饭点**：选填，不选就跟店一样；选了以菜自己的为准（4.5）。
- **能点外卖**：开关，默认关，由发布和编辑的人设。店里有能点外卖的菜，这家店就算能点外卖（4.2）。
- **评分**：吃过的同学可以给菜打 1–5 分，每人一个分数，可以改、可以撤销。有人评过就显示平均分（保留一位小数，「4.3 分」）和评过的人数。评分要认证。
- **一家店的一道菜只有一条**。第一个发布的人署名为上传者，后来的人通过赞、收藏和评论参与，不重复发布（见 9.2）。
- **编辑**：认证用户都能编辑菜品，但不能把菜换到别的店。每次修改留一条修改记录，所有人都能看，可以恢复到某个版本（9.4）。只有管理员能删除菜品。
- 菜的热度看赞数。菜收到的赞计入上传者的「获赞」。

### 4.4 分类

一道菜只属于一个分类。分类只用来排菜单和显示，不参与推荐；它也决定照片取色不可靠、或者没有舞台色时的默认舞台色。

| 分类     | 默认舞台色            |
| -------- | --------------------- |
| 主食     | 汤色 `stage-broth`    |
| 菜       | 酱色 `stage-soy`      |
| 小吃     | 辣橙 `stage-chili`    |
| 汤       | 竹屉 `stage-bamboo`   |
| 饮品甜品 | 芒果黄 `stage-mango`  |
| 特色     | 抹茶绿 `stage-matcha` |

「特色」给不好归类的菜用，是菜的分类，不是店的品类。店的品类和类型见 4.2，它们的默认舞台色见 4.7。

### 4.5 饭点

饭点回答「这顿是哪顿」，参与推荐。饭点属于店（4.2）；菜可以单独选饭点，不选就跟店一样。

| 饭点 | 时间段           |
| ---- | ---------------- |
| 早饭 | 05:00–10:00      |
| 午饭 | 10:00–15:00      |
| 晚饭 | 15:00–21:00      |
| 夜宵 | 21:00–次日 05:00 |

- 首页按当前时间自动显示饭点，用户可以手动切换。手动选择保持到当前时间段结束，进入下一个时间段后回到自动。
- 店铺记着自己做哪几顿：新建店时默认午饭、晚饭，编辑者可以改。
- 菜的饭点在发布和编辑菜时选，选填。没选的菜跟店一样；选了的以菜自己的为准。编辑时全部取消，就改回跟店一样。
- 早饭、夜宵时段只推荐带这个饭点的店；午饭、晚饭不按饭点筛（见第 8 节）。

### 4.6 标签

菜和店的口味（辣、麻、甜、酸、清淡）是它们自身的属性，见 4.2、4.3。口味之外还有下面两种标签，用途完全不同，界面上要让人分得清。

两种标签后端 v2 都暂不提供，App 里不放入口（「大家怎么说」的点词投票、「＋ 加标签」、「我的标签」、加菜页的「＋ 自己写」）。下面是接口补上之后的设计。

|          | 口味标签                                         | 我的标签                             |
| -------- | ------------------------------------------------ | ------------------------------------ |
| 是什么   | 大家对一道菜的评价，如「皮薄」「量大」「排队久」 | 自己给菜分的类，如「考试周」「请客」 |
| 谁看得见 | 所有人                                           | 只有自己                             |
| 词从哪来 | 运营维护的词表，只能从里面选                     | 自己写                               |
| 计数     | 每人对每道菜的每个词算一次，显示有多少人打过     | 不对外计数                           |
| 出现在   | 「大家怎么说」、消息                             | 我的标签、加标签面板的「＋ 自己写」  |

- 想要的口味词不在词表里时，可以用「＋ 自己写」写进「我的标签」，只有自己看得见，写的时候要明确提示这一点；也可以点「告诉我们」建议加进词表。
- 自己打过的口味标签可以撤回。

### 4.7 舞台色

舞台色从 9 个 `stage-*` 里选，决定当主角时整屏的颜色。取色、撞色、默认色的算法见设计规范「图片：插画与实拍」，产品上要求：

- **菜**：舞台色、两个备选色和封面裁切在发布时定下，随菜品保存，所有人看到的同一道菜颜色一致。发布和编辑的人可以在推荐的三个颜色里改选。没有保存的舞台色时用分类默认色（4.4），封面按居中裁切。
- **店**：餐厅详情和发现页的舞台色按店的类型和第一个品类定，所有人一致，盘子里招牌菜的照片不改变它。

  | 店         | 默认舞台色               |
  | ---------- | ------------------------ |
  | 米饭炒菜   | 酱色 `stage-soy`         |
  | 粉面       | 芒果黄 `stage-mango`     |
  | 火锅麻辣烫 | 红油 `stage-redoil`      |
  | 烧烤炸串   | 辣橙 `stage-chili`       |
  | 汤粥       | 汤色 `stage-broth`       |
  | 面点快餐   | 竹屉 `stage-bamboo`      |
  | 日韩料理   | 汤色 `stage-broth`       |
  | 甜点饮品店 | 青花蓝 `stage-porcelain` |
  | 没有填品类 | 汤色 `stage-broth`       |

- 转盘上相邻两家撞色时，后一家临时换用它第二个品类的颜色；也撞色就保持原色。不改店铺页的颜色。

### 4.8 专题

运营为一个校区挑的一组菜（5–20 道），有名字、一句介绍和起止时间，比如本周专题「期末续命餐」。每个校区同一时间最多一个当期专题，过期后进入「往期专题」。规则见 9.9。

后端 v2 暂缓专题：发现页的分类栏不放专题；菜品详情不显示专题提示。

### 4.9 评论

吃过这道菜的人留下的话，可以带照片。一道菜只有一条，后来的人的感受和实拍都落在评论里。评论的照片和上传者的照片一起出现在这道菜的大图里。规则见 9.8。

### 4.10 账号状态

| 状态   | 说明                                                                                                       |
| ------ | ---------------------------------------------------------------------------------------------------------- |
| 未登录 | 只能看登录页和协议。在登录页点「先逛逛」后成为游客，能浏览，不能看他人主页和消息，不能发布和互动（见 6.2） |
| 未认证 | 注册了，还没完成学生认证。能浏览，不能发布和互动                                                           |
| 已认证 | 通过山大统一认证或山大邮箱完成了认证。全部功能可用                                                         |

- 违规的账号由运营封禁，写明原因，可以定到期时间（到期自动解封），也可以是永久的。封禁中照常登录，只能浏览：
    - 能做的：看推荐、菜品、餐厅、附近、搜索、评论，看消息和他人主页，看收藏的店，屏蔽、登录设备、反馈和我的反馈、信息有误、举报、退出登录和注销账号。
    - 不能做的：发布、互动（赞、回应、收藏、评论、评价、评分、关注和取消关注、不想去这家）、编辑资料和账号设置（改密码、设用户名、认证、隐私和推荐设置），看历史、粉丝和关注列表、收藏的菜和经验明细。点了弹对话框「账号封禁中，暂时不能评论」（按动作换词），写原因和期限（「封禁至 11 月 30 日」或「永久封禁」）。
    - 「我的」舞台下方写「账号封禁中」、期限和原因；收藏的「菜」写「封禁期间暂时不能查看收藏的菜」。
    - 封禁时本人收到一条系统消息，写原因和期限（10.2）。

权限细节见第 7 节。管理工作（专题、商圈、删除店铺和菜品、举报处理、封禁）在后台完成，App 里没有管理入口。

### 4.11 等级

每个账号有一个等级，Lv.1 到 Lv.10，由累计经验决定。经验只增不减，升级不消耗经验。

- 获得经验：有哪些来源、每次得多少经验、每天最多几次由服务端定，在等级页的「经验规则」里列出（6.10）。每天第一次使用 App 得 5 经验，按北京时间算一天。只是看别人的主页不给对方加经验。
- 等级门槛（累计经验）：Lv.2 30、Lv.3 100、Lv.4 250、Lv.5 500、Lv.6 1000、Lv.7 2000、Lv.8 4000、Lv.9 8000、Lv.10 16000。门槛由服务端定，App 只显示服务端给的结果。
- 称号：由服务端定，目前只有满级有，叫「老吃家」。有称号时跟在等级后面，如「Lv.10 老吃家」。
- 谁能看到：等级和称号所有人都能看到；经验和经验明细只有自己看得见。
- 等级只用来展示，不解锁功能，也不影响推荐和权限。

### 6.2 登录（G-Login）

- 没登录时每次打开 App 都进登录页，退出登录、登录过期后也进登录页。我们希望大家登录使用，游客只是先看看的入口，所以不记住「上次是游客」。
- 页面上转盘慢慢转（90 秒一圈，系统开启减少动态效果时停住），品牌字「今天吃什么」，一句介绍。
- 两个黑色按钮：「手机注册 / 登录」在能用本机号码一键登录时拉起运营商的授权页，不能时打开手机号登录页；下面的「账号密码登录」直接打开密码登录页。注册和登录是同一个流程，没有单独的注册入口。
- 按钮下面是勾选框「我已阅读并同意《隐私政策》《用户协议》和《个人信息出境说明》」，默认不勾。一次勾选同时同意三件事，登录时一起提交（7.5）。
- **协议对话框**：没勾时点「手机注册 / 登录」「账号密码登录」或「先逛逛」，按钮照常可点（不置灰），点了弹对话框。
    - 内容：标题「同意后继续」，说明使用时会收集设备信息和使用记录，传到境外服务器存储和处理，请用户阅读并同意《隐私政策》《用户协议》《个人信息出境说明》，三份都带链接。
    - 按钮：主按钮「同意并继续」，次按钮「不同意」，和其他对话框一样。
    - 同意：勾选框一起勾上，直接继续刚才那一步，进对应的登录页或以游客身份进去，不用再点一次。
    - 不同意：关掉对话框，停在登录页，不再追问。
    - 已经勾了就不弹，直接继续。
- **先逛逛**：右上角的页角向左下卷起，露出下面一层纸色，上面写「先逛逛？」，卷起的页角后面探出一双眼睛（动画表情），像有人掀着页角往外偷看；点卷角不登录进去看看。这是登录页特有的入口，不用胶囊按钮。进页面时页角卷起来，按下时再多卷一点，之后每隔几秒把页角多掀起一点再弹回去，眼睛跟着多探出来一些；系统开启减少动态效果时直接显示卷好的样子，眼睛不动。没勾协议时先弹协议对话框。
    - 进去后到登录前要去的地方（比如分享链接指向的菜）；那个地方游客看不了，就进发现页。
    - 游客能看推荐、菜品、餐厅、附近、搜索、专题和评论，其余见 7.2。随时可以从「我的」或拦截对话框回到登录页，登录后回到原页面。
    - 游客状态只在这次打开内有效，下次打开回到登录页。
- **一键登录**（Android、iOS）：点「手机注册 / 登录」，从底部升起运营商的授权页：本机号码（中间几位打码）、运营商的标语、「本机号码一键登录」按钮、「其他号码登录」和运营商的服务协议。用户点登录后用本机号码登录，不用收验证码。
    - 授权页上的协议只有运营商那一份，勾选框默认不勾。没勾就点登录，弹一个确认框，点「同意并继续」后直接登录。
    - 没注册过的号码直接建号并登录，和验证码登录一样。
    - 点「其他号码登录」去手机号登录页；关掉授权页留在登录页。
    - 用不了一键登录时（没插卡、没开蜂窝网络、取号失败或超时、服务端没开，以及 Web）不提示，直接打开手机号登录页。
    - 授权之后登录失败：关掉授权页，弹对话框说明原因，主按钮「重试」重新拉起授权页，次按钮「用验证码登录」去手机号登录页。
    - 账号在注销冷静期内时见 7.7。
- **手机号登录**：输入手机号（只支持中国大陆手机号），点「获取验证码」，填 6 位验证码。验证码 5 分钟内有效，60 秒后可以重发，连续输错 5 次要重新获取。
    - 注册过的号码，验证后直接登录。
    - 没注册过的号码，验证后直接建号并登录，没有额外的确认步骤（勾选时已经同意，见 7.5），进入认证引导，可以「先逛逛」。
- **密码登录**：登录页抽屉里「手机注册 / 登录」下面有「账号密码登录」，手机号登录页上也有「用密码登录」；从登录页进入时「用验证码登录」换到手机号登录页。输入手机号或用户名，再输入密码。只有设过密码的账号能用，用户名要先在设置里设过才能用来登录（见 7.1）。
    - 页面上常驻一句「没设过密码的用验证码登录」。账号不存在、没设过密码、密码错，都就地提示「账号或密码错误」，不清空账号。
    - 同一个账号输错多次后，再登录要先过人机验证（12.4），通过后用刚填的账号密码直接登录，不用重填。
- **政策更新时**：登录时服务端说政策已经更新、要重新同意，弹同意对话框（7.5）。同意后用同一个验证码或同一组账号密码直接登录，不用重新获取验证码；一键登录时先关掉授权页再弹，同意后直接登录，不用重新授权；不同意就停在登录页。
- **封禁**：封禁的账号照常登录，登录后按封禁中处理（4.10）。
- 忘了密码直接用验证码登录，再去设置里改，不单独做找回流程。
- 登录成功后回到进登录页之前要去的地方（比如分享链接指向的菜），没有就进发现页。

### 6.3 认证（G-Verify）

- 认证只用来确认你是山大学生，不是登录方式。认证页写明「认证仅用于确认学生身份，我们无法获取你的统一认证密码」。
- 入口：注册后的认证引导、被拦下时的提示对话框、我的页的提示条、设置里的「认证」。
- 两种方式：
    1. 山大统一认证：跳转学校页面，完成后回到 App，由发起认证的账号确认后，结果记到这个账号上。
    2. 山大邮箱：填 `@mail.sdu.edu.cn` 或 `@sdu.edu.cn` 邮箱，收到链接后点开。Web 不上线，链接打开后去哪待定：以后加引导，正在和后端沟通。邮箱认证页要登录发起认证的那个账号才能完成；没登录时先去登录，登录后回到这一页。完成后显示结果，再进认证页。链接不属于当前账号或已经失效时提示「链接无效或已过期，请在发起认证的账号上打开」。
- 页面显示当前状态（未认证，或已认证及方式）。回到 App 时自动刷新状态，也可以点「我已完成，刷新状态」。
- 一个统一认证身份、一个邮箱只能认证一个账号。已经认证过别的账号时提示「该学号已认证其他账号」。
- 认证一次长期有效，毕业后不收回。
- 认证成功后，之前被拦下的操作立即可用，不用重新登录。

### 6.4 发现（G-HomePhoto、G2-Home）

App 的首页，也是最常用的页面。正式形态用实拍图（`G-HomePhoto`），`G2-Home` 的插画版只用于演示。画板按「一道菜」画，推荐改成店以后，舞台和抽屉按下面的描述做。

**顶部**

- 左边「在 软件园 吃 晚饭 ∨」是当前地点和饭点，选了点外卖时后面加「（外卖）」，点开是「在哪吃」面板。
- 右边是搜索和消息。在舞台上是两个带文字的胶囊（「搜索」「消息」）；往下翻到顶栏吸顶后收成两个图标。有未读消息时铃铛上加一个小圆点。

**舞台和转盘**

- 转盘一格是一家推荐的店，第一道招牌菜是主角，店是次要的。舞台显示：招牌菜名（大字）和价格，下面是店名、距离（或商圈名）、推荐率（规则见 9.7，没到门槛时不写），价格、店名和距离（或商圈名）前面带图标，店名最多两行，第二行不到第一行的三分之一时不换行，直接省略。没有招牌菜时店名是大字，不写价格。颜色是店的舞台色（4.7）。
- 盘子里是第一道招牌菜的封面；没有招牌菜时放门头照；都没有，或者图还没加载出来时是 `mist` 底，不用插画顶替。
- 左右拖动转盘或点「换一个」换下一家，一次只转一格，不自动轮播。
- 「就它了」进入这家店的餐厅详情。
- 「换一个」「就它了」右边是「不想去这家」图标按钮，点了弹对话框确认，不弹菜单：这家店 30 天内不再推荐，提示「30 天内不再推荐这家店」，转盘接着换下一家。游客点了弹登录对话框。
- 推荐一次给一批（8 家），舞台左下的小圆点表示在这一批里的位置。转过这一批的最后一家，接着是下一批，圆点从头开始。往回拨可以回到刚才看过的店。
- 能推荐的店都看过一遍后从头再来。能推荐的店少于 5 家时不用转盘，舞台只放当前这家，左右拖动和「换一个」照常可用。
- 店名按字数均分断行，每行不超过四个字，标点不出现在行首或行尾，字多时往下排成多行，最多四行（店名最长 20 个字）；四行放不下时每行多放一个字并缩小字号，不省略。
- 距离是从当前位置到店的直线距离，写「320 m」「1.2 km」。没有定位权限，或者人离校区超过 5 km 时，不显示距离，改显示商圈名。

**抽屉**

- 有普通公告时，抽屉顶部先占一条公告，可以关掉（见 12.2）。
- 分类栏：「美食」「甜点饮品」「自助」，各带一个图标（碗、饮品杯、餐盘罩），三格等宽，字在格里居中，底下一条细线。选中项加粗，字的下半截压一道舞台色的记号笔。
- 下面是推荐店的列表，往下滑继续加载，排成一份精选榜单。抽屉保持白底，每家店不加底色、边框和阴影，靠字号、字重和留白分层；不放门头照，店的样子由它的菜来撑。一家店压在约 240 高，展开抽屉时一屏能看到两家多。
    - 店名一栏：店名前面一个浅色大号序号（01、02），对应转盘上「这一批的第几家」。下面一行是推荐率的比例条和「86% 推荐」（规则见 9.7，没到门槛时不写），后面跟距离、商圈和第一个品类。只有店名跟在序号后面，其余文字和照片都从页面左边距开始，对齐在同一条线上。点这一栏进餐厅详情。
    - 菜排成同高的一行，第一道是店的脸，宽度是其他菜的两倍；用圆角方图直接放原图，不套盘沿（带盘沿的盘子只给舞台上的主角）。照片下面菜名一行、价格一行。只有一道时照片在左，菜名、价格和平均分（有人评过才写）在右。编辑者标过的招牌菜在菜名前加一个实心的「招牌」小签，不压在照片上。点一道菜进菜品详情。
    - 第一次出现时逐条淡入上移，照片按下时轻微缩小；系统开启减少动态效果时都不做。没有菜时只有店名一栏。加载中是同样排布的灰块。
    - 滑到底后继续上拉，整个推荐流跟着手指上移，松手回弹；转盘固定在底下不动。滑到最上面就停住，再往下拉是刷新。
    - 「美食」是更多推荐，和转盘一样受地点、饭点和堂食外卖影响；「甜点饮品」是甜点饮品店的推荐，「自助」是自助店的推荐。
- 分类栏只影响抽屉里的列表，转盘只推美食。
- 列表底部留出导航栏的高度。

**空状态**：当前地点和饭点下一家店都没有时，舞台换成插画和一句「这附近还没人加过店，发第一道菜」，按钮「发布一道菜」。抽屉里某一栏没有店时写「还没有推荐的店」，下面一句「换个饭点或校区看看，也可以发布第一道菜。」

**在哪吃面板**

- 底部面板，标题「在哪吃？」，三组单选：地点（已开放的校区，有定位时每个校区写出距离；另有「按定位」，默认打开，选离你最近的校区，见 4.1）、「吃哪顿？」（早饭、午饭、晚饭、夜宵，另有「按现在的时间」恢复自动）、「怎么吃？」（去店里吃、点外卖）。
- 怎么吃默认去店里吃，和校区一样记住上次的选择；饭点的手动选择只保持到当前时间段结束（4.5）。
- 点外卖时推荐能点外卖的店，不按距离排；去店里吃时只推荐附近的店（第 8 节）。
- 选完立即刷新转盘和列表，舞台换色。

**往期专题和专题页**（待接入）

- 往期专题：白底列表，每行是专题名、起止时间和三道菜的小圆图，按时间倒序。
- 专题页：标题是专题名，下面是介绍、起止时间和专题里的菜（两列方块）。从往期专题、消息进入。

### 6.5 菜品详情（G-Dish）

- 舞台：只占半屏。封面盘子、分类、菜名、价格。招牌菜在分类前加「招牌」，「招牌」和分类各是一个小胶囊。点盘子看大图：先是这道菜的照片，接着是评论里的照片，每张标出是谁拍的，左右翻看。
- 右上角：编辑、收藏、分享。和「我的」一样，在舞台上是带文字的胶囊（「编辑」「收藏」或「已收藏」「分享」），吸顶后收成图标。「编辑」进编辑菜品（6.9），认证用户都能编辑，没认证时点了弹拦截对话框。分享面板里是分享渠道和「复制链接」；看别人的菜时最后多一项「举报」。
- 菜品详情看的是这一道菜，和餐厅详情（看一份菜单）分开：舞台只有一只大盘子，抽屉的主体是评论。
- 抽屉从上到下：数字条、上传者卡片、店三张卡片照 Material 3 Expressive 的分段列表连成一组，卡片之间只隔一道窄缝，整组外侧是大圆角，相邻卡片接缝处是小圆角；按住上传者卡片或店，这一张四个角都变成大圆角，松开复原。
    - **数字条**：一行三格，从左到右是评分、赞、口味，每格上面一行小字说明，中间是数字，下面一行补充。
        - 口味：这道菜的口味（4.3），只读，最多 3 个；没填时写「—」，下面「还没标口味」。不放点词投票和「＋ 加标签」（4.6）。
        - 赞：心形加赞数，下面写「点一下赞」，赞过写「你赞过」。点这一格赞或取消；赞上时心形弹一下、向外散开一圈小点，数字往上翻一格。
        - 评分：上面写「12 人评分」（没人评过只写「评分」），中间是平均分（「4.3」），没人评过时写「—」；下面一排五颗小星是自己打的分，没打过是空星。点这一格，评分卡从这一格展开（见下）。
    - **上传者卡片**：上面是这道菜的说明，下面一行头像、昵称、「10 月 18 日上传」，点击进他人主页。游客看到的昵称写「同学」，上传者的账号已经不在时写「已注销用户」，点了没有反应。
    - **店**：放在上传者卡片下面。门头照（小圆角的方图）、店名、距离、商圈和楼层，点击进餐厅详情。「导航去店里」只放在餐厅详情。
    - **吃过的人说**：放在最下面。标题后面跟评论条数。标题下面就是写评论的输入框（见下），再下面是最有用的 3 条，最后「看全部 23 条」进全部评论。一条都没有时写「还没有人说过，来写第一条」。
    - 最底下一行小字：「修改记录」，所有人都能看（见下）。
- **评论的样子**：照抖音的评论区排，不画卡片，条与条之间不画线，只靠留白分开。左边头像；右边一行灰色的昵称，上传者自己的评论后面带「上传者」小标；下面是文字、照片（最多 3 张小图，点开看大图）；昵称和文字的右边是「回复」和一个大箭头，点它或文字都是回复，长按文字打开「更多」的菜单。最下面一行是时间（变浅）、「回应」，有人回应过时接着是表情回应的胶囊，这一行右边是赞（心形加数，赞上时心形弹一下）和「更多」。有回复时挂在评论的文字下面，和文字对齐，头像小一号，昵称写成「小林 回复 阿哲」；先露出最早的 2 条，「—— 展开 5 条回复」看全部，还有没加载的写「展开更多」，全部展开后写「收起」。「更多」里自己的是「删除」，别人的是「举报」。
- **表情回应**：有人回应过时，最下面一行「回应」后面每种回应一个胶囊（放不下时横着滑），表情加人数，自己选的那种描边；点胶囊选上或取消这一种。点「回应」，和评分卡一样从这个按钮展开成一张卡片：「回应这条评论」（回复是「回应这条回复」），六种表情（大拇指、爱心、笑哭、惊讶、难过、好吃）排成一行，下面是各自的人数，自己选过的那种带底色。点一种就选上，表情弹一下，再点是取消；卡片不关，点卡片外面或右上角关闭。表情用 Twemoji 的图片。
- **评分卡**：点数字条的评分格，那一格自己长大成一张浮在遮罩上的卡片：位置、大小和底色一起过渡，格子里原来的内容先淡出，卡片内容再淡入；关的时候收回那一格。卡片上是「给这道菜打分」和菜名，中间五颗星，下面写这个分数的说法（不好吃、一般、还行、好吃、必吃），最下面一行提示和这道菜现在的平均分。点一颗星就提交，也可以按住左右滑、松手时选中，亮起的星依次弹一下；卡片不关，平均分和人数跟着更新；再点一次已选的那颗撤销。提交失败时退回原来的分数并提示原因。点卡片外面或右上角关闭。评分要认证（4.3）。
- **全部评论**：白底，顶部切换「最有用」「最新」，下面就是写评论的输入框，再下面是评论。
- **写评论**：不跳新页面，在评论区就地写。平时是一条「吃过的话，说两句」的胶囊，右边一个相机；点胶囊，胶囊自己长成多行输入框（底色、描边、高度一起过渡，相机向右收起）、弹出键盘，下面一行是加照片、「全屏」，右边是字数和贴着右边的「发送」。没内容时点框外面收回成胶囊。文字最多 200 字，照片最多 3 张，两样至少有一样。点相机（胶囊旁边的或框里的）都和评分卡一样，从相机展开一张「加照片」卡片，选「从相册选」或「拍一张」；在胶囊旁边点的，选到照片才展开输入框，没选就保持胶囊。「全屏」让输入框从原处展开铺满屏幕，同一份草稿接着写，写长的时候方便；退出全屏时收回原处。发出后清空、收起，提示「发送成功」。没发出就离开页面时确认「放弃这条评论？」。
- **回复**：参照抖音，点评论或回复右边的「回复 >」（或文字），屏幕最下面弹出一条横条，贴着键盘：输入框里写「回复 小林」，只能写字，框里右边是「全屏」，横条最右边是「发送」。输入框随字数长高，最多 5 行。发出后收起；点横条外面也收起，写了内容时先确认「放弃这条回复？」。
- **加标签面板**（待接入）：上面是口味词表，多选，自己打过的是选中态；下面是「＋ 自己写」，写的标签进「我的标签」，旁边提示「只有你自己看得见」；最底下一行小字「词表里没有想要的？告诉我们」，进反馈并带上这道菜。
- **修改记录**：白底列表，最新的在前。每行是谁改的、什么时候、改了哪些地方（「修改了价格、口味」「恢复到之前的版本」），第一行标「当前版本」。其余每行有「恢复」，确认「恢复到这个版本？」后把菜改回那次修改后的内容，恢复也记一条；和当前一样时提示「已经是这个版本」。恢复要认证。
- 未认证时：点赞、回应、收藏、评分、评论、关注、编辑、恢复时弹拦截对话框（见 7.3）。
- App 里不能删除菜，菜有问题可以举报，由管理员删除。
- 看过的菜记入历史。
- 菜已经被删除时，显示「这道菜已删除」，可以返回。

### 6.6 餐厅详情（G-Detail）

- 餐厅详情看的是一份菜单，和菜品详情（看一道菜）分开：舞台上是几只招牌盘子，抽屉的主体是分好组的菜单。
- 舞台：招牌菜的盘子扇形排开，最多 3 只，第一道在中间最大，点了进那道菜；没有招牌时是一只装门头照的盘子，门头照也没有时放菜单的第一道菜。舞台色按店的类型和品类定（4.7）。左下是店名（占满一行，最多两行，放不下时字号缩小）、地址。
- 右上角：编辑、收藏店铺、分享。在舞台上是带文字的胶囊（「编辑」「收藏」或「已收藏」「分享」），吸顶后收成图标。「编辑」进编辑店铺，认证用户都能编辑，没认证时点了弹拦截对话框。
- 抽屉从上到下：
    - **数字条**：一行三格，和菜品详情的数字条同一个样子。下面接一张品类和口味的卡片，两张照菜品详情那样连成一组（6.5）。
        - 推荐率：「86%」，规则见 9.7，写的是外卖的推荐率时这一格叫「外卖推荐率」；不满门槛时写「—」。下面写「32 人评过」，不满门槛时写「2 条评价」或「还没人评价」；自己评过时写自己的评价（「你：堂食推荐」）。点这一格，和菜品详情的评分卡一样，从这一格展开评价卡（见下）。
        - 菜单：菜数和「道菜」写在一起（「13 道菜」）。
        - 距离：「320 m」，下面写商圈和楼层。
    - **品类和口味**：一张卡片两行，左边小字「品类」「口味」，右边用顿号连起来（「粉面」「辣、酸」）。没有品类也没有口味时不放这张卡片。
    - **导航去店里**：打开手机上的地图 App，装了几个就让用户选，目的地是这家店。Web 上打开网页版地图。
    - **加一道菜**：进入发布第 2 步，店已经选好。
    - **全部菜品**：标题后面跟菜数。按菜单顺序：招牌菜在前，然后按分类（主食、菜、小吃、汤、饮品甜品、特色），同一类里赞多的在前。相邻的同一类收成一组，每组一个小标题（「招牌 3」「主食 5」），下面是两列菜品方块。方块上赞数前面写平均分（「4.3 分」），有人评过才写（4.3）。没有菜时写「这家店还没有菜」。
    - 最底下一行小字：「修改记录」「信息有误」。
- **评价卡**：点数字条的推荐率格，和菜品详情的评分卡一样从那一格展开。卡片上是「评价这家店」和店名，下面「堂食」「外卖」各一行，每行「推荐」「不推荐」，点一个就提交，已有的评价是选中的，可以改选，再点一次已选的撤回；卡片不关，最下面一行提示和我现在的评价。点卡片外面或右上角关闭。评价要认证。
- **编辑店铺**：白底页，可以改店名、地址描述、门头照、类型、品类、口味、饭点、价位，以及「这家店已关门」。只提交改过的内容；改店铺不查重（9.2）。改过内容后返回时确认是否放弃。认证用户都能编辑，没认证时点了弹拦截对话框。位置不在这里改，位置不对用「信息有误」告诉我们。能不能点外卖也不在这里改，在菜上设（4.2）。
- **修改记录**：和菜品的修改记录一样（6.5）：谁改的、什么时候、改了哪些地方，第一行标「当前版本」，其余可以恢复。
- **信息有误**：选一项（店名不对、位置不对、已关门、和别的店重复、其他），补充说明选填，最多 200 字。提交后提示「已提交，核实后会通过消息通知你」。
- **已关门的店**：舞台上地址下面写「这家店已关门」，「导航去店里」「加一道菜」不可用，其余照常能看。
- **已删除的店**：显示「这家店已删除」，可以返回。
- 看过的店记入历史。

### 6.7 附近（G-Nearby）

- 地图当舞台，中心是当前位置，没有定位权限时是校区中心。每家店是一个圆形标记，里面是店的封面（第一道招牌菜的封面，没有时用门头照）；选中的那家放大、外圈加它的舞台色、下面写店名。
- **搜索**：顶部搜索框「搜店名或地址」。结果直接落在地图和抽屉里，显示店名或地址对得上的店；找菜去搜索页（6.8）。清空搜索回到附近。没结果时写「没找到「酸辣粉」」和「换个店名或地址试试。」
- **筛选**：搜索框右边的「筛选」胶囊（图标加「筛选」两个字）打开底部面板：
    - 类型：不限、美食、甜点饮品、自助，单选。
    - 品类：米饭炒菜、粉面、火锅麻辣烫、烧烤炸串、汤粥、面点快餐、日韩料理，多选。
    - 价位：不限、¥15 以下、¥15–30、¥30 以上，单选。
    - 只看口碑好的：至少 3 条评价，推荐率不低于 70%（堂食、外卖有一个满足就算）。
    - 只看我收藏的店。游客打开时弹登录对话框。
    - 底部「重置」和「看 12 家」，数字随选项实时变化。有筛选时按钮上显示选了几项。筛完一家都没有时写「没有符合筛选的店」和「清空筛选」。
- **商圈**：搜索框左边一个胶囊，写当前选中的商圈「舜泰广场」，没选时写「附近」。点开是底部面板「选商圈」：
    - 顶部搜索框「搜商圈」，按名字找。
    - 「最近」：最近选过的商圈。
    - 「全部」：第一项「附近」，表示不限商圈；后面是商圈，按离我的距离排，没有定位时按离校区中心排，每个写距离「560 m」。
    - 商圈都排成多行胶囊，不横向滑动。点一个就选中并关上面板。
    - 选中商圈后，地图移到这个商圈并画出范围，列表只看这个商圈的店，抽屉标题写「舜泰广场 12 家」；选「附近」回到按地图中心找。默认选中当前所在的商圈，不在任何商圈里时是「附近」。
- 右下「回到我的位置」，跟着抽屉上沿走；抽屉拉高到放不下时收起来，不压在搜索框上。
- **抽屉**：「附近 18 家」，按距离排，离地图中心近的在前。每行是店的封面缩略图、店名、距离、商圈和楼层、「招牌：鲜虾蟹籽云吞」（有招牌菜时），右边是推荐率（规则见 9.7）。
- 点地图标记：选中这家，列表滚到它；再点一次进餐厅详情。
- 点列表行：先在地图上选中这家，地图移过去（不重新查附近的店），抽屉拉得太高时落回初始高度；这一行下面出现引导「在地图上了，再点一次进店」，再点这一行或引导进餐厅详情。没有地图时直接进餐厅详情。
- 拖动地图后，按新的地图中心重新加载附近的店。新结果回来之前地图和列表接着显示上一次的店，「附近 8 家」下面走一条加载条，结果回来再换，不退回灰块。
- 拖抽屉时地图不动。
- 抽屉可以上拉展开、下拉收起。
- 已关门的店不出现。

### 6.8 搜索（G-Search）

- 从发现页右上角进入，白底，自动弹出键盘。
- 搜菜名、店名和地址，结果分「菜」「店」两栏，默认停在「菜」；菜没有结果、店有结果时停在「店」。
    - 菜：两列菜品方块，按菜名找，不限校区，可以按饭点筛选，默认不限饭点，已关门的店的菜不出现，最新发布的在前，写距离，不写商圈。
    - 店：和附近抽屉一样的行，按店名、地址和店里的菜名找，离你近的在前，已关门的店排在最后并标明。因为菜名搜到的店，行里写搜到的那道菜和价格，如「有「鲜虾云吞」¥18」。
- 没输入时显示最近搜过的词，最多 10 个，可以清空。游客搜过的词不保存。
- 没结果时写「没找到」，认证用户多一个「新建一家店」。

### 6.9 发布一道菜

入口：导航栏右边的「＋」；餐厅详情的「加一道菜」（跳过第 1 步）；发现页空状态的「发布一道菜」；搜索没结果时的「新建一家店」（建好店后直接进第 2 步）。未认证时点入口弹拦截对话框，不进入流程。

中途关闭时，如果已经填了内容，确认「这道菜还未发布，确定放弃吗？」。不存草稿。

发布即公开，不审核（9.10）。

**第 1 步：选店（G-PickShop）**

- 标题「在哪家吃的？」，搜索框「搜店名」。
- 提示「你在万达金街附近，离你近的排在前面」。没有定位时不显示这句，按离校区中心的远近排序。
- 单选列表：店的封面缩略图、店名、距离、商圈和楼层。已关门的店不出现。
- 底部「没找到？新建一家店」。
- 主按钮「下一步：给袁记云饺加菜」，没选店时不可用。

**新建店**

- 先从地图上的店里选：搜索框「搜店名」，带上选店页里已经输入的关键词。按关键词搜当前位置附近（没有定位时搜校区中心附近）的地图地点，候选列表显示店名、地址和距离。
- 选中一个候选后，店名、位置、地址描述按地图上的信息预填，用户可以改，限制和手动添加一样。
- 选中的地点已经有人建过店时，提示「这家店已经有了，叫「袁记云饺」」，可以「就选它」，也可以「继续新建」（食堂里几个窗口共用一个地点时用得上）。继续新建的店不和这个地图地点关联。
- 候选列表底部「搜不到？手动添加」，手动填：
    - 店名：必填，最多 20 个字。
    - 位置：必填，地图选点，默认当前位置。地图默认锁定，点「调整位置」后才能拖动地图让中心对准店门口，点「用这个位置」确认，或点「取消」放弃。所属商圈按位置自动判断并显示出来，不用填。
    - 地址描述：必填，最多 30 个字，提示「比如 万达金街 1 层」。
- 类型：必选，「美食」「甜点饮品」或「自助」（4.2）。没选时提交按钮上方写「请选择店铺类型」。
- 门头照片：选填，1 张，提示「拍一张招牌，别人更好找」。
- 其余选填，带默认值：品类（最多 2 个，默认不选）、口味（最多 3 个，默认不选）、适合哪顿（默认午饭、晚饭，至少留一个）、价位（默认不填）。能不能点外卖不在店上填，在加菜时设（4.2）。
- **已有的店**：选中的地图地点已经有店时，店名下提示「这家店已经有了，叫「袁记云饺」」；200 m 内有同名的店（忽略空格和大小写）时提示「附近已有一家「袁记云饺」，相距 80 m」。由服务端查，只是提示：可以「就选它」，也可以「不是同一家，继续新建」（食堂里几个窗口共用一个地点时）。
    - 提交时服务端发现可能已有这家店：提示「附近可能已有这家店」，列出那家店，同样可以选它或者继续新建。
- 建好后回到第 2 步，店已选好。

**第 2 步：加菜（G-AddDish）**

- 舞台：封面照片和它的舞台色，旁边小字「主色取自照片」。还没加照片时，舞台用汤色，盘子位置是一个虚线圆「加一张照片」。
- 照片条：已加的照片、「＋」再加一张、已加几张和上限（「2 / 9」）。照片可以拍，也可以从相册多选。第一张加好后自动进入调整照片，之后加的照片不用调整。点封面可以重新调整，也可以把别的照片设为封面，换封面后重新调整。
- 照片加进来就开始上传，和填表同时进行，失败的单张可以重试。App 切到后台时不保证继续上传，回到前台后每张失败的照片自动重试一次。
- 抽屉：
    - 「发布到 袁记云饺」和「换一家」。
    - 菜名、价格（见 9.1）。
    - 分类：单选，主食、菜、小吃、汤、饮品甜品、特色。
    - 口味：辣、麻、甜、酸、清淡，最多 3 个；选第 4 个时提示「口味最多选 3 个」。不放「＋ 自己写」（4.6）。
    - 适合哪顿：选填，早饭、午饭、晚饭、夜宵，可以多选。不选就跟店里一样，下面写「跟店里一样，午饭、晚饭」（不知道店的饭点时写「不选就跟店里一样」）。
    - 能点外卖：开关，默认关。
    - 招牌菜：开关，说明「每家店最多 3 道招牌菜」。这家店已经有 3 道时，提交后在开关下提示「这家店已有 3 道招牌菜，先取消一道」。
    - 说两句：选填，最多 200 字，提示「好吃在哪，有什么要注意的」。
- 分类、口味、饭点的选项，以及照片、口味、招牌菜的上限由服务端定，目前照片最多 9 张；取不到时用内置的值：照片 6 张、口味 3 个、招牌菜 3 道。
- **按照片预选**：菜名填好、第一张照片传完、还没选分类时，按菜名和照片预选分类和口味，分类旁写「按照片预选，可以改」，手动改过后这句消失。预选失败不提示，照常手动选。每次发布最多预选一次。
- 输完菜名就由服务端查重。这家店已有同名菜时，输入框下提示「这家店已有鲜虾蟹籽云吞」和「去看看」，不能发布。点「去看看」进那道菜并打开写评论，已经加的照片带过去。
- 主按钮「发布」。必填项没填完时不可用，按钮上方用 `warn` 写缺哪些必填项，如「请填写价格和分类」。照片没传完时按钮显示进度。
- 发布成功后进入这道菜的菜品详情，提示「发布成功」；从详情返回时回到发起发布的页面。失败时留在本页，内容不丢，说明原因。

**编辑菜品**

- 从菜品详情的「编辑」进入，用加菜页，表单按现有内容预填。认证用户都能编辑。
- 店不能换：顶部写「所在的店 袁记云饺」，没有「换一家」。
- 照片整组替换：点「换照片」重新选一组，保存后替换原有的全部照片，提示「保存后替换原有的 3 张照片」，旁边「不换了」撤回。不换照片时，舞台色和封面裁切也不变。
- 改了菜名同样查重，重名时提示「这家店已有同名的菜，换个菜名」。
- 饭点按这道菜自己选的预填；没选过的不预填，跟店里一样。把选了的饭点全部取消，保存后改回跟店里一样。
- 不按照片预选。没有改动时不能保存，主按钮是「保存」。保存后提示「已保存」，回到菜品详情。
- 没保存就离开时确认「修改还未保存，确定放弃吗？」。

**调整照片（G-Crop）**

- 拖动、双指缩放，把主菜放进圆圈里，默认居中。底部的缩放滑条是不能用手势时的替代。
- 舞台颜色：三个推荐色，默认第一个，下面实时预览「首页会是这样」。照片太灰时把分类默认色排第一；这时还没选分类就先用汤色，选了分类后自动换成分类默认色，用户手动选过颜色就不再动。
- 「取消」放弃这次调整，「完成」保存裁切和颜色，回到第 2 步。

### 6.10 我的（G-Me）与他人主页

**我的**

- 舞台：我获赞最多的那道菜的封面和舞台色。还没发布过菜时用芒果黄 `stage-mango` 加插画空盘。
- 头像、昵称、用户名（设过才显示）、签名（全部写出来，不截断，舞台跟着变高）。昵称右边是等级胶囊「Lv.3」，有称号时带上称号，如「Lv.10 老吃家」，点了进「等级」（4.11）。统计：获赞、上传的菜、粉丝、关注，粉丝和关注可以点进列表。获赞是我上传的菜收到的赞，加上我的评论和回复收到的赞。
- 右上角：「历史」（最近看过的菜和店）、「编辑资料」和设置。和发现页的搜索、消息一样，在舞台上是三个带文字的胶囊（「历史」「编辑」「设置」），往下翻到顶栏吸顶后收成三个图标。
- 吸顶和发现页一样：舞台固定在底下，往上翻时抽屉盖上来；内容分栏翻到顶栏下面时停在那里。吸顶后顶栏左边是头像和昵称。
- 不放「我的标签」（4.6）。
- 内容分栏（各带一个图标：上传、书签、心形、对话）：
    - 上传：我发布的菜，两列方块，菜名右边是赞数。
    - 收藏：顶部一条铺满整行的矮胶囊开关切换「菜」「店」，换的时候列表淡入。菜是两列方块；店是和附近列表一样的榜单条目，右边带门头小图。
    - 赞过：我赞过的菜，两列方块，最近赞的在前。
    - 评论：我写过的评论，每行是菜的缩略图、菜名、我说的话和时间，点进菜品详情并滚到这条，这条的底色亮一下再褪掉。
- 未认证时舞台下方加一条「认证后可以发布和互动」和「去认证」。
- 游客：舞台用芒果黄 `stage-mango` 加插画空盘，下面一句「登录后看你的收藏、评论和发布」和主按钮「登录」，不显示统计、分栏和快捷入口。右上角只留设置，设置里只有「个性化」「检查更新」和「关于」；关于里的「反馈」「我的反馈」点了弹登录对话框（7.3）。

**他人主页**

- 从菜品详情的上传者、评论者、消息、粉丝和关注列表进入。
- 舞台、签名和统计和「我的」一样，昵称右边也有等级胶囊，但点了没有反应。对方没公开粉丝或关注列表时，那一项的数字写「–」。右上角是「关注」「已关注」或「回关」，旁边「更多」里是「屏蔽」和「举报」。
- 内容只有「上传」一栏。收藏、赞过、评论、标签和历史是私人的。
- 粉丝、关注列表能不能点开，按对方的隐私设置；不公开时写「对方未公开」。

**粉丝、关注**：头像、昵称、关注按钮，点行进他人主页。

**我的标签**（待接入）：列出我写过的标签和各自用了几次，可以改名、删除。删除只去掉标签，不影响菜。点一个标签进「标签下的菜」，两列方块。

## 7. 账号、认证与权限

### 7.1 账号与登录

- 「沙软今天吃什么」是同学自己做的产品，和学校没有隶属关系。山大统一认证只用来确认学生身份，不是登录方式。
- 一个手机号对应一个账号。用手机号加验证码登录，App 上也可以用本机号码一键登录（6.2），新号码第一次登录时自动注册；设了密码后也可以用手机号或用户名加密码登录。
- 账号有**用户名**和**昵称**，注册时都不用填。
    - 用户名是登录用的名字，不能和别人重复，3–10 位字母、数字或下划线，区分大小写。没设时系统内部有一个默认值，但不显示、也不能用来登录；在设置里设一次（见 6.12），设好后不能再改。设过之后在「我的」和账号与安全里显示，可以用来密码登录。
    - 对外展示的是昵称，随时能改，可以用中文，不要求唯一。注册时系统给一个默认昵称，第一次进「我的」时提示改昵称和头像。
- 手机号只用来登录和确认身份，不对外展示。
- 注册后是未认证状态，完成认证（见 6.3）后变成已认证。认证结果跟着账号走，换设备不受影响。
- 校外的人能注册，但没法认证，只能浏览。

### 7.3 拦截方式

- 按钮照常显示，不隐藏、不置灰，让人知道有这个功能。
- 游客点了弹对话框：「登录后才能点赞」（按动作换词），主按钮「去登录」，次按钮「先逛逛」。进游客看不了的页面（消息、他人主页、发布）的入口也照常显示，点了弹同一个对话框，如「登录后才能看消息」。登录后回到点之前的页面，不自动替用户完成刚才的动作。
- 未认证时点了弹对话框：「认证后才能点赞」（按动作换词），主按钮「去认证」，次按钮「先逛逛」。
- 账号状态在别处变了（比如在网页上完成了认证），下一次操作时按新状态处理。刚被封禁时，下一次被服务端拒绝的操作弹封禁对话框，之后按封禁中处理（4.10）。

### 7.4 登录态

- 登录后一直保持，直到用户退出、长时间没用、申请注销，或者在别的设备上改了密码、换绑了手机。封禁不会让登录失效（4.10）。在一台设备上改密码、换绑手机，或设置用户名时顺便设了密码，其他设备要重新登录，这台设备不受影响；只设用户名不用重新登录。
- 失效时回到登录页，登录后回到原页面。
- 游客状态不保存：关掉 App 再打开、退出登录、登录过期后都回到登录页，要再点一次「先逛逛」。
- 同一账号可以同时在手机和 Web 上登录。
- 退出登录时清掉这台设备上的登录信息和个人数据。

### 7.5 数据存放在境外

账号信息、照片、位置等数据存放在境外服务器，要用户同意数据跨境。由用户自己点同意，客户端不代用户同意。

- 隐私政策和数据跨境说明共用一个版本号，由运营在后台发布，改动就发新版本。《隐私政策》《用户协议》《个人信息出境说明》是托管的网页，在 App 里打开网页看。
- **登录时**：登录页的勾选框一次同意隐私政策、用户协议和数据存放在境外（6.2）。验证码登录和密码登录都带上当前政策的版本，新号码注册时一并记下同意；还没发布过政策时不带。
- **登录时政策刚好更新**：服务端说没带同意或版本不对，弹同意对话框。同意后用同一个验证码或同一组账号密码直接重试，不用重新获取验证码；不同意就停在登录页。
- **使用中政策更新**：服务端要求重新同意时弹对话框，标题「隐私政策已更新」，一句话说明服务器位于境外、账号信息和使用记录会传到境外存储和处理，附《隐私政策》《个人信息出境说明》链接，按钮「同意」「不同意」。同意后继续刚才的操作；不同意，这次操作失败，下一次操作再问。登录后和已登录时打开 App，也向服务端核对一次：政策在上次同意后更新过，就弹同一个对话框；不同意时，之后的操作仍会再问。同一时间只弹一个同意对话框。
- 没有单独的同意页面，设置里没有「数据存放」入口。设计稿里的 `G-RegisterConfirm`、`G-DataNotice`、`G-Reconsent` 只作为对话框文案的参考。
- 数据存在境外、存哪些信息，写进《隐私政策》。同意隐私政策即开启使用统计（12.5），可以在设置 → 隐私里单独关闭，关闭时删除已经收集的记录；不同意统计不影响其他功能。

### 7.6 个人信息

- 只收集用得到的：手机号（登录用）、用户名和密码（选设）、认证信息（认证方式、学号、姓名）、昵称、头像、签名、位置、设备信息、使用记录。
- 设备信息（型号、系统版本、设备标识）和使用记录（看了什么、点了什么）用于账号安全、风控、推荐和改进产品，范围见 12.4、12.5。
- 学号和姓名在认证时由学校返回，用来确认一人一号、处理违规，不展示给任何其他用户。
- 位置只在需要时使用，用来算距离、找附近的店和判断商圈；不在后台定位，不记录轨迹。
- 不收集性别、生日、家乡。
- 隐私政策和用户协议在登录页和设置里都能看到。
- 游客也要先同意隐私政策（6.2）：浏览同样会用到设备信息和使用记录。《隐私政策》里写明不登录时收集什么（设备信息、使用日志、位置），不收集手机号。

### 7.7 注销账号

- 入口：设置 → 账号与安全 → 注销账号。
- 注销页说清楚后果：
    - 会删除：资料、认证信息、收藏、我的标签、历史、关注关系、屏蔽列表；我给别人的赞、口味标签和店铺评价从计数里去掉。
    - 由用户选：评论和回复。注销页有一项「同时删除我的评论和回复」，默认不选；不选时内容匿名保留，作者显示「已注销用户」。
    - 会保留：我上传的菜和新建的店，它们是店铺菜单的一部分，始终匿名保留；上传者显示「已注销用户」，点了没有反应。
- 确认前要用手机验证码验证身份。
- 确认前要验证身份：绑定了手机号的用发到这个号码的验证码（发送前过人机验证）；没有手机号的（以前用用户名注册的）用密码。
- 申请后有 7 天冷静期，期间账号不能用，所有设备都退出登录；在提交申请的设备上重新登录，用密码或手机验证码验证通过就撤销注销，账号照常使用；7 天后彻底删除。
- 冷静期内在别的设备上登录，提示「账号注销中，在申请注销的设备上重新登录可以撤销」，不能登录。
- 一键登录不能撤销注销。冷静期内用一键登录：在提交申请的设备上转到手机号登录页，提示「账号注销中，用验证码登录可以撤销」；在别的设备上停在登录页，提示同上一条。
- 封禁中也能注销。
- 注销完成后，同一个手机号可以注册新账号，用过的统一认证身份和邮箱也可以给新账号认证。

## 8. 推荐

推荐的单位是店，不推单道菜。发现页的转盘和抽屉列表按下面的规则出店，每家店带上它的招牌菜（最多 3 道，只用来展示，不参与排序）。

- **范围**：当前校区、没关门的店。转盘和「美食」一栏只推美食，「甜点饮品」一栏推甜点饮品店，「自助」一栏推自助店（4.2）。
- **堂食和外卖**：在「在哪吃」面板里选（6.4），是同一套推荐，筛选和侧重不同。
    - 去店里吃：有位置时只推离你 3 km 内的店；以堂食推荐率为主，距离其次。
    - 点外卖：只推能点外卖（店里有能点外卖的菜，4.2）、或者有人评过外卖的店，有位置时在 5 km 内找，不按远近排；以外卖推荐率为主，外卖评价少时参考堂食推荐率，但打折扣。
- **饭点**：早饭、夜宵时段只推做这一顿的店；午饭、晚饭不按饭点筛（4.5）。
- **质量**：以口碑为主。推荐率按评价条数平滑，评价少的店不会靠一两条好评排到最前；热度和新店只有少量加分，新店也有被看到的机会。最近 7 天评价过（吃过）的店往后放。
- **多样**：同一个商圈、同一个品类不连续出现超过 2 家。排序里带一点随机，同一天翻页时顺序不变。
- **不重复**：登录用户同一天推过的店不再推，当天的店都推过一遍后从头再来。
- **不想去这家**：在转盘上标了「不想去这家」的店，30 天内不再推（6.4）。
- **因人而异**：参考你明确做过的事，统计你偏爱的口味和品类：赞过、收藏过的菜，收藏过、评价过的店，越近的越算数。偏爱的口味和品类给店加分，推荐偏好页里只读显示。推荐偏好（设置 → 隐私 → 推荐偏好，6.12）里还可以自己填喜欢的品类和口味、忌口（只能选辣、麻）、价位和最远距离（只对去店里吃生效）：喜欢的加分，忌口的店不推。不参考浏览历史。在设置里关掉「个性化推荐」后不再参考个人记录和推荐偏好（6.12）。
- 游客看到的推荐不带个人因素，没有去重，也不能标「不想去这家」。

## 9. 内容规则

### 9.1 发布字段

**菜**（发布和编辑相同，编辑时不能换店）

| 字段             | 必填 | 规则                                                                               |
| ---------------- | ---- | ---------------------------------------------------------------------------------- |
| 店               | 是   | 选已有的店，或新建                                                                 |
| 照片             | 是   | 第一张是封面，上限由服务端定，目前 9 张；太大的图先压缩                            |
| 封面裁切、舞台色 | 是   | 默认居中、默认第一个推荐色                                                         |
| 菜名             | 是   | 1–12 个字，去掉首尾空格；同一家店不能重名（9.2）                                   |
| 价格             | 是   | 0–999 元，最多一位小数，显示时整数不写小数。称重、自选这类不固定的，填一个常吃的价 |
| 分类             | 是   | 主食、菜、小吃、汤、饮品甜品、特色，6 选 1；可以按照片预选                         |

口味标签和我的标签见 4.6（待接入）。

**店**（新建和编辑相同，编辑时不改位置）

| 字段     | 必填 | 规则                                           |
| -------- | ---- | ---------------------------------------------- |
| 店名     | 是   | 1–20 个字，去掉首尾空格；附近同名时提示（9.2） |
| 位置     | 是   | 地图选点，默认锁定，点「调整位置」拖动，「用这个位置」确认或「取消」；所属商圈按位置自动判断 |
| 地址描述 | 是   | 1–30 个字                                      |
| 类型     | 是   | 美食、甜点饮品、自助                           |

| 品类     | 否   | 最多 2 个                                      |
| 口味     | 否   | 最多 3 个                                      |
| 饭点     | 是   | 至少 1 个，新建时默认午饭、晚饭                |
| 价位     | 否   | ¥15 以下、¥15–30、¥30 以上，默认不填           |
| 已关门   | 否   | 只在编辑时出现                                 |

店不填「能点外卖」，由店里的菜汇总：有能点外卖的菜，这家店就算能点外卖（4.2）。

### 9.2 查重

- **菜**：同一家店里菜名相同（忽略空格和大小写）就算重复，不能发布，引导去已有的那道写评论。编辑时改成重名的菜名也不能保存。两个人同时发布同一道菜时，后发的按重复处理。
- **店**：
    - 新建时，选中的地图地点已经有店，或者 200 m 内有同名的店（去掉空格、忽略大小写后相同），提示已有的店，只提示、不拦：用户可以选已有的店，也可以确认「不是同一家」后继续新建。
    - 一个地图地点可以有几家店（食堂里几个窗口共用一个地点），继续新建时新店照样关联这个地点。
    - 修改店铺不查重。
    - 真重复的店由同学通过「信息有误」反馈，运营合并。

### 9.3 照片

- 必须是这道菜的实拍。不能用网图、插画、菜单截图，靠举报兜底。
- 封面上舞台和转盘时，用圆形裁切加盘沿（`DishPlate`）。其他照片看大图时原样显示。
- 推荐流的方块直接用封面原图，不套盘沿。
- 评论里的照片同样要是这道菜的实拍，出现在这道菜的大图里，排在上传者的照片后面。

### 9.4 编辑与删除

- 认证用户都能编辑任何一道菜和任何一家店。菜不能换店；改菜名、改店名时同样查重（9.2）。编辑后赞、收藏、评论都保留。
- 每次新建、修改、恢复都记一条修改记录：谁改的、什么时候、改了哪些地方。招牌菜的标记也记在菜的修改记录里。修改记录所有人都能看。
- 认证用户可以把菜或店恢复到修改记录里的某个版本，恢复也记一条修改记录。被乱改时靠恢复兜底，故意乱改的人可以举报。
- 只有管理员能删除菜和店，App 里没有删除入口。删除后从所有地方消失，菜的评论一起删除，也从别人的收藏里去掉，赞不再计入获赞；相关消息点进去提示「这道菜已删除」「这家店已删除」。

### 9.5 口味

- 菜和店的口味只有辣、麻、甜、酸、清淡五个，各自最多 3 个，由发布和编辑的人选，改动记进修改记录。
- 发布时可以按菜名和照片预选（6.9），只是建议，用户可以改。
- 推荐按口味给你偏爱的店加分；忌口只能选辣、麻（第 8 节）。
- 「大家怎么说」的口味标签投票待接入（4.6）。接上后：词表由运营维护，可以增删改，改名后已打的标签跟着改；每人对每道菜的每个词只算一次，可以撤回；最多显示 6 个，按人数排序。

### 9.6 我的标签（待接入）

- 每个最多 10 个字，不能重名。
- 只有自己看得见，可以改名、删除。

### 9.7 店铺评价

- 吃过以后先选「堂食」或「外卖」，再选「推荐」或「不推荐」。只给店，不给菜。
- 认证用户每人对每家店、每个场景一个评价，可以改选、可以撤回。每次评价同时记一次「吃过」，推荐会把最近 7 天吃过的店往后放（第 8 节），撤回评价不删这条记录。
- **推荐率** = 选「推荐」的条数 ÷ 这个场景的评价条数，四舍五入取整。堂食、外卖分开算。
- 舞台和店铺行以堂食为主：堂食满 3 条时写「86% 推荐」，下面小字「32 人评过」；堂食不满、外卖满 3 条时写「外卖 80% 推荐」；都不满 3 条时写评价条数，如「2 条评价」；没人评过写「还没人评价」。
- 附近的「只看口碑好的」：堂食或外卖有一个场景至少 3 条评价、推荐率不低于 70%。
- 只显示汇总，不公开谁评了什么。

### 9.8 评论

- 认证用户才能写。一条评论最多 200 字、最多 3 张照片，文字和照片至少有一样。
- **回复**只有一层：回复别人的回复时写「回复 小林」，仍然挂在同一条评论下面。回复只能写字，最多 200 字。
- **排序**：默认「最有用」，赞多的在前，赞数一样新的在前；可以切到「最新」。菜品详情只露最有用的 3 条。
- **赞**：评论和回复都能被赞，收到的赞计入作者的「获赞」。
- **表情回应**：评论和回复都能回应，认证用户才能回应。每人对一条只留一种，换一种就替换原来的，再点自己选的那种是取消。
- **删除**：作者能删自己的评论和回复，不能编辑。删掉评论时下面的回复一起消失。菜的上传者不能删别人的评论，只能举报。
- 菜被删除时评论一起删除。

### 9.9 专题

后端 v2 暂缓专题，下面的规则在接口补上后做（4.8）。

- 运营为一个校区挑一组菜（5–20 道），写名字、一句介绍和起止时间。每个校区同一时间最多一个当期专题。
- 当期专题出现在发现页分类栏，过期后进入往期专题。
- 菜被收进专题时，用系统消息通知上传者。
- 专题里的菜被删除后，自动从专题里去掉。

### 9.10 不审核、举报与屏蔽

- **不审核**：菜、店、评论都是发布即公开，不经过审核，也没有「审核中」的状态。问题内容靠举报和管理员删除处理；菜和店被改错时可以恢复到之前的版本（9.4）。
- **举报**：菜、评论和回复、用户都能举报。入口：菜品详情的分享面板、评论的「更多」、他人主页的「更多」。原因：不是这道菜的实拍、广告、违法或不友善、其他，补充说明选填。提交后提示「已提交，我们会尽快处理」。
- **处理**：运营处理举报，结果用系统消息通知举报人。多次违规的账号会被封禁，封禁中只能浏览（4.10）。
- **屏蔽**：在他人主页屏蔽一个人后：
    - 他的评论和回复对你隐藏；
    - 他对你的赞、评论、回复、关注不再通知你；
    - 他不能再关注你，已有的关注关系解除；
    - 他上传的菜还在店铺菜单里。
    - 设置 → 隐私 → 屏蔽的人，可以解除屏蔽。

### 9.11 文案

按设计规范「内容与语气」。产品层面再补两条：

- 同一个动作全程同一个叫法：「换一个」「就它了」「加一道菜」「发布」「导航去店里」「写一条」「去认证」。
- 提示和报错用规范短句，说清结果和下一步：「网络连接失败，请重试」，不写「请求失败（40001）」这样的错误码，也不写「网络不太好，再试一次」这样的口语。

## 10. 消息与通知

### 10.1 消息页（G-Inbox）

- 从发现页右上角的铃铛进入，白底。
- 大标题「消息」，旁边「3 条未读」；右上角「全部已读」。
- 分栏：全部、评论、赞和收藏、关注、系统。
- 按「今天」「本周」「更早」分组，组内按时间倒序。
- 每行：未读圆点（7px，读过去掉）、对方头像、一句话、时间，右边是相关菜的缩略图或操作按钮。
- 点一行就算读了，并跳到对应的地方。
- 消息之间用细线分开。
- 系统消息在列表里显示全文，不截断，时间放在标题同一行右边。有去处的（反馈结果、举报结果、新设备登录）把详情收进标题下面的一个浅色块（设备名和「不是本人登录时，可以让它下线」，或运营回复和「查看处理详情」），点这个块才跳转；点这一行的其他地方只算读了，不离开消息页。

### 10.3 规则

- 对自己的内容操作不产生消息。
- 取消赞、取消收藏、撤回标签不产生消息，已经发出的消息不撤回。
- 同一个对象、同一类消息（赞、收藏、评论、回复、关注）在同一天的合成一条，如「Momo 等 12 人赞了……」，显示最新那个人，时间是最新那次。反馈结果、举报结果、公告一条一行。
- 关注消息里，我还没关注对方时显示「回关」，关注后变成「已互关」。
- 屏蔽的人的互动不产生消息。
- 铃铛的未读圆点在回到 App 前台、回到发现页时刷新。

### 10.4 推送

- 推送和你有关的事：评论、回复、赞和收藏、关注、系统消息。不推饭点提醒，不推营销内容。
- 赞和收藏合并后再推，同一道菜 1 小时内的合成一条：「Momo 等 5 人赞了你上传的番茄牛腩饭」。评论、回复、关注、系统消息一条一推。
- 23:00–08:00 不推送，这段时间的消息只进消息页。
- 设置 → 通知里按类型开关：评论和回复、赞和收藏、关注、系统消息，默认都开。
- 不在第一次打开时要推送权限。第一次发布成功后再问：「有人赞你的菜、评论你的菜时告诉你？」，拒绝后可以在设置里重新打开。
- 点推送直接进对应的页面，和点消息一样。

|                        | Android、iOS                              | Web                            |

| 统一认证（只用于认证） | App 内打开学校页面，完成后回到 App        | 跳转学校页面再跳回             |
| 定位                   | 系统权限                                  | 浏览器权限                     |
| 加照片                 | 拍照或相册                                | 选文件，手机浏览器可以直接拍   |
| 导航去店里             | 选已安装的地图 App（iOS 包括 Apple 地图） | 打开网页版地图                 |
| 分享                   | 系统分享面板                              | 支持时用系统分享，否则复制链接 |
| 打开分享链接           | 装了 App 打开 App，没装时打开轻量分享页面 | 直接打开                       |
| 推送                   | 有                                        | 没有，只看消息页               |

### 11.2 屏幕尺寸

设计稿按 390 × 844 画，其他尺寸按下面的规则伸缩。

- **手机宽度（600 以下）**：内容铺满，左右边距保持 `space-20`，中间随宽度伸缩，两列方块等分宽度。窄于 360 时，舞台菜名和价格的字号按宽度缩小，菜名最小 36px，每行仍不超过四个字。
- **宽屏（600 及以上：平板、折叠屏展开、电脑浏览器）**：有舞台的页面（发现、菜品详情、餐厅详情、我的、他人主页）让舞台铺满整个屏幕，抽屉变成左侧的白色悬浮面板（宽 400），菜名、价格、按钮和盘子排在面板右边。面板里的内容单独滚动，舞台不动。发现页的地点、搜索、通知收进面板顶部；转盘沿着屏幕右边缘上下转，下一道从右上角露出来。
- **附近页的宽屏**：同样的排法，地图铺满整个屏幕代替舞台，商圈胶囊在搜索框左边，列表和地图同时看。
- **宽屏的底部导航**：发现、附近、我的三个页面的导航都放在左侧面板底部，切换时位置不动。
- **宽屏的白底页面**：消息、搜索、设置这类白底页面放在居中的一栏里，最宽 480。
- **高度**：舞台高度随屏幕高度变化，844 高时是 520；矮屏按比例缩小，最矮 420，盘子和转盘跟着缩；高屏最高 560，多出来的高度给抽屉。舞台上的菜名、价格和按钮贴着舞台底部排，保证不被抽屉盖住。我的和他人主页例外：舞台只放得下头像、昵称、签名和统计就够，抽屉默认露出更多内容。
- **方向**：手机只竖屏。平板和电脑浏览器横竖都行，按宽屏规则排。
- **安全区**：避开刘海、灵动岛、屏幕圆角和安卓手势条。顶部栏在状态栏下面，底部导航在 24px 之外再加系统的底部安全区。
- **深色模式**：默认跟随系统的深浅设置，也可以在设置 → 个性化里固定浅色或深色（6.12）。舞台色压暗一些，还是同样 9 种颜色，文字色不变；舞台上的盘子不分深浅；地图底图换成深灰；抽屉、白底页面、面板、对话框和底部导航换成深色底、浅色字。

### 11.3 字号与输入

- 正文、列表、按钮文字跟随系统字号，最大跟到 2 倍；底部导航、胶囊标签这类尺寸固定的控件最大到 1.3 倍；舞台菜名、价格、页面大标题不跟随。
- 字号放大后文字可以换行，不能被截断或互相压住，按钮跟着变高。
- 输入框获得焦点时自动滚到看得见的位置；底部主按钮（下一步、发布、发送）浮在键盘上方。
- 用读屏软件能完整走完主要流程（登录、换菜、看详情、发布），细则见设计规范「无障碍」。

## 12. 运行保障

上线后靠下面这些手段及时修问题、调策略、防滥用。这里写它们在用户那边表现成什么样、能做什么、不能做什么；具体用什么技术实现，写在技术架构和依赖选型文档里。

### 12.1 版本与更新

| 方式     | 什么时候用                         | 用户看到什么                                                               |
| -------- | ---------------------------------- | -------------------------------------------------------------------------- |
| 热更新   | 修问题、小调整                     | 后台下载，下次打开生效，没有提示；在设置里点「检查更新」时提示已下载       |
| 建议更新 | 商店里有新版本                     | 发现页弹一次「有新版本」，按钮「去更新」「下次再说」，同一个版本只提示一次 |
| 强制更新 | 版本太旧没法正常用，或者有安全问题 | 打开 App 直接进更新页，只能去更新。尽量少用                                |

- 热更新只用于修复问题和不改变功能范围的小改动。新功能、新权限、新的数据收集，都要发新版本、过商店审核。
- 热更新补丁导致打不开时，自动退回上一个能用的版本。
- 补丁先发给一部分人，没问题再放到所有人；有问题可以暂停或撤回。
- 设置 → 关于里显示版本号和补丁号，反馈问题时能说清楚。

### 12.2 远程配置与公告

不发版就能调整的内容：

| 类别     | 内容                                                             |
| -------- | ---------------------------------------------------------------- |
| 功能开关 | 发布、新建店、评论、推送、专题等，可以单独关闭                     |
| 运营参数 | 饭点时间段、推荐每批几道、分类栏顺序、推荐率的显示门槛、风控阈值 |
| 公告     | 普通公告、重要公告                                               |
| 维护     | 全站只读、停服维护                                               |
| 版本     | 建议更新、强制更新的版本线                                       |
| 实验     | A/B 测试的分组（见 12.3）                                        |

- **功能关闭**：入口照常显示，点了提示「该功能暂时关闭」，有原因时写上原因。
- **公告**：普通公告在发现页抽屉顶部占一条，可以关掉，关掉后同一条不再出现；重要公告在打开 App 时弹窗，看过一次不再弹。公告可以按校区、平台、版本分别发。
- **维护**：只读时能看不能发，发布、评论等按钮照常显示，点了提示「系统维护中，暂停发布，预计 23:30 恢复」；停服时打开 App 显示维护页，写明预计恢复时间。
- 配置拉不到时用上次拿到的，从没拿到过就用内置的默认值，不能因为配置失败影响使用。
- 远程配置不能用来：打开新的数据收集或权限、改变隐私政策里承诺的做法、绕过商店审核上线新功能。

### 12.3 A/B 测试

- 用来验证体验上的改动，比如推荐每批几道、转盘按钮的文案、发布页字段的顺序、推送的时机。
- 按账号分组，同一个人在一个实验里始终在同一组，换设备也一样。
- 同一个人同时最多在 3 个实验里，会互相影响的实验不放在同一个人身上。
- 这些不做实验：隐私和权限、协议和同意、举报和屏蔽、安全和风控提示、价格和距离的真实性。任何一组都不能少掉核心功能。
- 每个实验开始前写清楚：验证什么、看哪个指标（见 12.5）、跑多久（一般 1–4 周）、怎样算赢。结束后全量上线或撤掉，不留长期分叉。
- 隐私政策里说明会做这类测试，不单独告诉用户自己在哪一组。

### 12.4 风控

目标是防刷量、防广告和骚扰、保护账号，同时不误伤正常同学。

- **原则**：拦下时说清楚原因和什么时候能恢复，不悄悄失败；觉得被误伤可以通过反馈申诉。下面的数字都是初始值，用远程配置调整。
- **验证码**：同一手机号 60 秒一次、1 小时 5 次、1 天 10 次。每次发验证码前都先过人机验证：判断没有风险时自动通过，用户看不到；有风险时才需要用户手动验证。超限时按服务端给的等待时间提示，如「发送太频繁，请 9 小时后再试」。
- **登录**：同一个账号密码输错多次后，再用密码登录要先过人机验证；同一个人在同一网络下连续输错 5 次，15 分钟内不能再用密码登录，可以用验证码登录。别人乱试不会把你的账号锁住。在新设备上登录时，其他设备收到系统消息「你的账号已在新设备上登录」，不是本人可以去设置 → 登录设备把它下线。
- **注册**：同一台设备一天最多注册 3 个账号。
- **频率**：每人每天最多发 20 道菜、建 5 家店、写 100 条评论和回复。操作太快（比如 1 分钟赞 30 次）先提示「操作过于频繁，请稍后再试」，继续就暂时限制。到了上限提示「今日发布已达上限，请明天再试」。
- **内容**：发布前不审核（9.10）。照片里有二维码、联系方式、广告，说明和评论里放链接和联系方式的，靠举报删除。
- **刷量**：同一台设备上多个账号的赞、口味标签、店铺评价只算一次；异常集中的赞和评价不计入，涉嫌刷量的账号交给运营处理。
- **自动限制**：轻度违规时自动限制对应的操作一段时间（比如 24 小时不能评论），其他功能照常，提示里写原因和恢复时间。严重或多次违规由运营封禁（见 4.10）。
- 风控要识别设备，这一点写进隐私政策（见 7.6）。

### 12.5 数据与指标

- 统计大家怎么用产品，用来改进体验和判断 A/B 测试的结果。
- **会采集**：看了哪些页面、点了哪些按钮（换一个、就它了、导航去店里、发布等）、停留时长、崩溃和出错、设备型号、系统版本、App 版本。
- **不采集**：输入框里没发出去的内容、相册里没选的照片、通讯录、后台位置。
- 统计数据只用于整体分析和排查问题，不对外提供，保存 7 天。
- 用户可以在设置 → 隐私里关闭使用统计（7.5），关闭时删除这个人已经收集的记录。

| 指标                     | 怎么算                                     | 为什么看                 |
| ------------------------ | ------------------------------------------ | ------------------------ |
| 定下来的人数（核心指标） | 每周点过「就它了」或「导航去店里」的人数   | 直接反映有没有帮人定下来 |
| 换菜次数                 | 从打开发现页到「就它了」平均换了几次       | 太多说明推荐不准         |
| 定下来用时               | 从打开发现页到「就它了」的时间             | 越短越好                 |
| 内容供给                 | 每周新发布的菜和评论数，带照片的评论单独看 | 有没有人在贡献           |
| 内容覆盖                 | 有菜的店的占比、每家店平均几道菜           | 内容够不够用             |
| 认证率                   | 注册 7 天内完成认证的比例                  | 认证引导有没有用         |
| 留存                     | 本周用过、下周还来的人的占比               | 长期价值                 |
| 健康                     | 被举报和被删内容的占比、崩溃率、加载失败率 | 社区和稳定性             |

### 12.6 出问题时

- 推荐拿不到时，转盘先用上一次的那批，提示「网络连接失败，显示的是上次的推荐」。
- 没网时，看过的发现页、菜品详情、我的页可以看缓存；发布、评论等要联网的操作提示没网，填的内容不丢。
- 地图出问题时，附近页退回只有列表。
- 推送出问题不影响消息页。
- 某个功能后端出问题时，先用功能开关把它关掉（见 12.2），其他功能照常。
