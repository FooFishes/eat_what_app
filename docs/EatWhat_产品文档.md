# EatWhat 产品文档

> 2026-10-22 初稿。2026-10-25 改：账号有用户名，人机验证每次发验证码前都过。

本文描述「沙软今天吃什么」的最终形态：为谁做、解决什么问题、每个功能具体怎么表现。它是开发的依据，回答「做成什么样」，不讲「怎么实现」。

- 行为和规则以本文为准。视觉守设计原则，`prototype/` 是 2026-10-22 的设计快照，供参考；具体排布由 App 定，见 `EatWhat_设计与实现.md`。画板和本文对不上时以本文为准。
- 本文不涉及接口、数据结构和技术方案，这些写在 `EatWhat_技术架构.md`。
- 现有接口、画板和本文之间的差距，以及差距补上之前怎么过渡，见 `EatWhat_现状差距.md`。

## 1. 产品是什么

**一句话**：沙软今天吃什么，帮山东大学软件园校区的同学在饭点一下子定下吃什么，再把吃到的好菜分享给同学。

**要解决的问题**

1. 饭点选择困难。软件园周边的店不少，但每天能想起来的就那几家。打开外卖或点评 App，面对的是几百家店、满屏满减和广告，越刷越定不下来。
2. 好吃的信息散在宿舍群和口口相传里。新生不知道西门小吃街哪家好，老生吃到好菜也没地方留下来。食堂窗口这类店，外部平台几乎没有收录。

**我们的回答**

- 一次只给一道具体的菜：哪道菜、哪家店、多远、多少钱。不满意就「换一个」，满意就「就它了」，然后去店里。
- 内容来自同校同学的实拍、口味标签和评论，不接商家，不做广告。
- 以菜为单位，不以店为单位。同学之间推荐的从来是「袁记的鲜虾云吞」，不是「袁记云饺 4.5 分」。

| | 外卖、点评平台 | 宿舍群 | 沙软今天吃什么 |
| --- | --- | --- | --- |
| 单位 | 店 | 一句话 | 一道菜 |
| 范围 | 全城 | 看群友 | 校区周边，包括食堂窗口 |
| 怎么帮你定 | 排序筛选，自己挑 | 问了再说 | 直接给一道，换到满意为止 |
| 内容来源 | 商家和所有用户 | 同学 | 认证过的同学 |
| 商业 | 广告、推广 | 无 | 无 |

## 2. 为谁做

### 2.1 用户

| 用户 | 他们要什么 | 主要用到 |
| --- | --- | --- |
| 软件园在读学生（主要用户） | 饭点前几分钟定下吃什么，不想多想 | 发现、菜品详情、导航 |
| 爱吃、爱分享的同学 | 把好菜留下来，被人看到、被人赞 | 发布、评论、我的、消息 |
| 刚到软件园的同学（新生、换校区的研究生） | 摸清周边有哪些店、哪些值得去 | 附近、餐厅详情 |
| 校外或还没认证的人 | 看看软件园的同学都在吃什么 | 只能浏览，不能发布和互动 |

只面向山大在读学生。最先开放软件园校区，之后按校区逐个开放（见 4.1）。

### 2.2 典型场景

**饭点纠结**。11:50 下课，打开 App 落在发现页。舞台上是「鲜虾蟹籽云吞，袁记云饺，320 m，¥18」。不太想吃，左滑换成「番茄牛腩饭」，再点「换一个」到「柳州螺蛳粉」。就它了，进菜品详情看一眼大家说「汤鲜」「量大」，点「导航去店里」打开地图。

**和室友约饭**。在菜品详情点分享，发到宿舍群。室友点开链接，装了 App 的直接进这道菜，没装的打开 Web 版。

**吃到好吃的**。吃完拍一张，点导航栏右边的「＋」。选店（离你近的排在前面），加照片，把菜拖进圆圈，选一个舞台色，填菜名、价格、分类、适合哪顿，勾两个口味标签，发布。

**已经有人发过**。想发的菜别人已经发过了。输完菜名，App 提示「这家店已有鲜虾蟹籽云吞」，带他去那道菜，刚拍的照片已经放进评论框，他补一句「加了辣油更好吃」发出去。

**刚到软件园**。打开附近，地图上是周边店铺的招牌菜。切到「西门小吃街」，筛一下「¥15 以下」，沿着列表一家家看，进店看「招牌」「大家怎么说」和推荐率。

**收到反馈**。手机上弹出「小林收藏了你上传的鲜虾蟹籽云吞」。打开 App，消息里还有「你上传的玉米鲜肉饺子已被收录到本周专题「期末续命餐」」，有人关注了你，顺手回关。

## 3. 产品原则

做取舍时按这几条来，排在前面的优先。

1. **帮人定下来，而不是让人挑**。发现页的主角永远是一道具体的菜，交互围绕「换一个」和「就它了」。列表、筛选、排序都是配角。
2. **一道菜是最小单位**。店是菜的归属，推荐、标签、赞、收藏、评论都落在菜上。
3. **真实优先**。舞台上只放用户实拍，插画只用于空状态、引导和演示。不接商家投放，推荐位不卖。
4. **少打字**。用口味标签代替长评；菜用赞，店用四档评价，都不打星。发布控制在两步，必填项尽量少。
5. **不藏功能**。做不了的事也让人看见，并告诉他怎么才能做。比如没认证时点赞，告诉他去认证，而不是把按钮藏起来。
6. **引导亲切，提示规范**。文案短、直接：引导像同学之间说话，提示和报错用规范短句。用词按设计规范「内容与语气」。

## 4. 核心概念

### 4.1 地点：校区和商圈

- **校区**是「在哪吃」，决定推荐、附近和专题的范围。首页左上角显示当前校区，点开可以切换。开放哪些校区由运营决定，最先开放软件园。
- 第一次打开时，按定位选离你最近的已开放校区，没有定位就选软件园。之后记住你上次选的。
- **商圈**是校区周边一片店铺聚集的区域，有地理边界，比如「万达金街」「银座商城」「校内食堂」「西门小吃街」。一个校区包含若干商圈。
- 一家店按位置归入一个商圈，也可以不属于任何商圈。
- 食堂也是商圈，食堂里的每个窗口算一家店，比如「二餐 2 楼麻辣烫」。

### 4.2 店

- 一家店有：店名、位置、地址描述（「万达金街 1 层」「B1」）、所属商圈、门头照片（选填）。
- 店由认证用户在发布流程里新建。同一位置不应该有两家同名的店（见 9.2）。
- **招牌菜**是这家店获赞最多的几道菜。店的封面、地图标记都用第一道招牌菜的封面。
- **价位**是这家店菜价的中间值，用于附近的筛选，分「¥15 以下」「¥15–30」「¥30 以上」三档。
- **店铺评价**是同学对整家店的四档评价：推荐、还不错、一般、不推荐，对外显示推荐率（见 9.7）。菜不打这个评价，菜用赞和口味标签。
- **状态**：正常或已关门。同学反馈「已关门」，运营核实后标为已关门：不再出现在推荐和附近里，搜索还能搜到，餐厅详情写明「这家店已关门」。
- 店铺资料由运营维护。用户发现不对，在餐厅详情里点「信息有误」告诉我们。

### 4.3 菜

- 一道菜属于一家店，有：菜名、价格、分类、适合的饭点、照片（1–9 张，第一张是封面）、封面的圆形裁切和舞台色、说明、口味标签、评论。
- **一家店的一道菜只有一条**。第一个发布的人署名为上传者，后来的人通过赞、收藏、口味标签和评论参与，不重复发布（见 9.2）。
- 菜的热度看赞数。菜收到的赞计入上传者的「获赞」。

### 4.4 分类

一道菜只属于一个分类。分类也决定照片取色不可靠时的默认舞台色。

| 分类 | 默认舞台色 |
| --- | --- |
| 主食 | 汤色 `stage-broth` |
| 小吃 | 辣橙 `stage-chili` |
| 饮品 | 芒果黄 `stage-mango` |
| 甜品 | 青花蓝 `stage-porcelain` |
| 汤 | 竹屉 `stage-bamboo` |
| 火锅 | 红油 `stage-redoil` |
| 烧烤 | 酱色 `stage-soy` |
| 凉菜 | 抹茶绿 `stage-matcha` |
| 配菜 | 抹茶绿 `stage-matcha` |
| 其他 | 竹屉 `stage-bamboo` |

### 4.5 饭点

饭点回答「这顿是哪顿」，参与推荐。

| 饭点 | 时间段 |
| --- | --- |
| 早饭 | 05:00–10:30 |
| 午饭 | 10:30–14:30 |
| 晚饭 | 14:30–20:30 |
| 夜宵 | 20:30–次日 05:00 |

- 首页按当前时间自动显示饭点，用户可以手动切换。手动选择保持到当前时间段结束，进入下一个时间段后回到自动。
- 发布时给菜选适合的饭点，可以多选，默认勾上当前饭点。
- 推荐只出适合当前饭点的菜，不够时用其他菜补齐（见第 8 节）。

### 4.6 标签

两种标签用途完全不同，界面上要让人分得清。

| | 口味标签 | 我的标签 |
| --- | --- | --- |
| 是什么 | 大家对一道菜的评价，如「皮薄」「量大」「排队久」 | 自己给菜分的类，如「考试周」「请客」 |
| 谁看得见 | 所有人 | 只有自己 |
| 词从哪来 | 运营维护的词表，只能从里面选 | 自己写 |
| 计数 | 每人对每道菜的每个词算一次，显示有多少人打过 | 不对外计数 |
| 出现在 | 「大家怎么说」、消息 | 我的标签、加标签面板的「＋ 自己写」 |

- 想要的口味词不在词表里时，可以用「＋ 自己写」写进「我的标签」，只有自己看得见，写的时候要明确提示这一点；也可以点「告诉我们」建议加进词表。
- 自己打过的口味标签可以撤回。

### 4.7 舞台色

每道菜有一个舞台色，从 9 个 `stage-*` 里选，决定它当主角时整屏的颜色。取色、撞色、默认色的算法见设计规范「图片：插画与实拍」，产品上要求：

- 舞台色、两个备选色和封面裁切在发布时定下，随菜品保存，所有人看到的同一道菜颜色一致。
- 上传者可以在推荐的三个颜色里改选，编辑菜品时也能改。
- 转盘上相邻两道撞色时，后一道临时用它的第一个备选色，不改保存的值。

### 4.8 专题

运营为一个校区挑的一组菜（5–20 道），有名字、一句介绍和起止时间，比如本周专题「期末续命餐」。每个校区同一时间最多一个当期专题，过期后进入「往期专题」。规则见 9.9。

### 4.9 评论

吃过这道菜的人留下的话，可以带照片。一道菜只有一条，后来的人的感受和实拍都落在评论里。评论的照片和上传者的照片一起出现在这道菜的大图里。规则见 9.8。

### 4.10 账号状态

| 状态 | 说明 |
| --- | --- |
| 未登录 | 只能看登录页和协议 |
| 未认证 | 注册了，还没完成学生认证。能浏览，不能发布和互动 |
| 已认证 | 通过山大统一认证或山大邮箱完成了认证。全部功能可用 |
| 封禁中 | 因违规被封禁。能浏览，不能发布和互动，显示原因和解封时间 |

权限细节见第 7 节。管理工作（口味词表、专题、商圈、店铺资料、举报处理、封禁）在后台完成，App 里没有管理入口。

### 5.2 明确不做

| 不做 | 原因 |
| --- | --- |
| 年夜饭、家乡美食地图等活动 | 和「今天吃什么」无关 |
| 商家入驻、广告、付费推广 | 违背「真实优先」 |
| 点餐、外卖、团购、支付 | 只负责帮人定下来，不做交易 |
| 星级评分、分数 | 菜用赞和口味标签，店用四档评价（见 9.7），不出现几颗星、几点几分 |
| 私信、群聊、约饭组局 | 社交只做到关注、评论和消息 |
| 饭点提醒、营销推送 | 推送只用来告诉你和你有关的事（见 10.4） |
| App 里的管理功能 | 管理在后台完成 |
| 采集性别、生日、家乡 | 没有用到这些信息的功能，按最少够用原则不采集（见 7.6） |
| 深色模式 | 颜色跟着菜走，舞台色深浅写死，不另做深色主题 |
| 多语言 | 只做简体中文 |
| 桌面端 | 只做 Android、iOS、Web |

### 6.2 登录（G-Login）

- 第一次打开、退出登录、登录过期后进入登录页。没有游客模式。
- 页面上转盘慢慢转（90 秒一圈，系统开启减少动态效果时停住），品牌字「今天吃什么」，一句介绍。
- 一个主按钮「手机号登录」，打开白底页面。注册和登录是同一个流程，没有单独的注册入口。
- 先勾选「我已阅读并同意《隐私政策》和《用户协议》」才能继续。没勾时「手机号登录」显示成灰色，点了不进下一页：协议那一行晃一下，勾选框下面用 `warn` 写「请先勾选同意协议」；勾上后按钮变回正常、提示消失。
- **手机号登录**：输入手机号（只支持中国大陆手机号），点「获取验证码」，填 6 位验证码。验证码 5 分钟内有效，60 秒后可以重发，连续输错 5 次要重新获取。
  - 注册过的号码，验证后直接登录。
  - 没注册过的号码，验证后直接建号并登录，没有额外的确认步骤（数据存放见 7.5），进入认证引导，可以「先逛逛」。
- **密码登录**：手机号登录页上有「用密码登录」，输入手机号或用户名，再输入密码。只有设过密码的账号能用，没设过时提示「该号码未设置密码，请使用验证码登录」；用户名要先在设置里设过才能用来登录（见 7.1）。出错时就地提示「账号或密码错误」，不清空账号。
- 忘了密码直接用验证码登录，再去设置里改，不单独做找回流程。
- 登录成功后回到进登录页之前要去的地方（比如分享链接指向的菜），没有就进发现页。

### 6.3 认证（G-Verify）

- 认证只用来确认你是山大学生，不是登录方式。认证页写明「认证仅用于确认学生身份，我们无法获取你的统一认证密码」。
- 入口：注册后的认证引导、被拦下时的提示面板、我的页的提示条、设置里的「认证」。
- 两种方式：
  1. 山大统一认证：跳转学校页面，完成后回到 App，结果记到当前登录的账号上。
  2. 山大邮箱：填 `@mail.sdu.edu.cn` 或 `@sdu.edu.cn` 邮箱，收到链接后点开完成。
- 页面显示当前状态（未认证，或已认证及方式）。回到 App 时自动刷新状态，也可以点「我已完成，刷新状态」。
- 一个统一认证身份、一个邮箱只能认证一个账号。已经认证过别的账号时提示「该学号已认证其他账号」。
- 认证一次长期有效，毕业后不收回。
- 认证成功后，之前被拦下的操作立即可用，不用重新登录。

### 6.4 发现（G-HomePhoto、G2-Home）

App 的首页，也是最常用的页面。正式形态用实拍图（`G-HomePhoto`），`G2-Home` 的插画版只用于演示。

**顶部**

- 左边「软件园 晚饭 ∨」是当前地点和饭点，点开是「地点和饭点」面板。
- 右边是搜索和消息。有未读消息时铃铛上加一个小圆点。

**舞台和转盘**

- 舞台显示当前这道菜：菜名、店名、距离、价格，颜色是这道菜的舞台色。
- 左右拖动转盘或点「换一个」换下一道，一次只转一格，不自动轮播。
- 「就它了」进入这道菜的菜品详情。
- 推荐一次给一批（8 道），舞台左下的小圆点表示在这一批里的位置。转过这一批的最后一道，接着是下一批，圆点从头开始。往回拨可以回到刚才看过的菜。
- 能推荐的菜都看过一遍后从头再来。能推荐的菜少于 5 道时不用转盘，舞台只放当前这道，「换一个」照常可用。
- 菜名按词断行，每行不超过四个字，字多时往下排成多行（菜名最长 12 个字，最多三行，见 9.1）；排到三行时缩小字号，不省略。
- 距离是从当前位置到店的直线距离，写「320 m」「1.2 km」。没有定位权限，或者人离校区超过 5 km 时，不显示距离，改显示商圈名。
- 封面没加载出来时盘子里是 `mist` 底，不用插画顶替。

**抽屉**

- 有普通公告时，抽屉顶部先占一条公告，可以关掉（见 12.2）。
- 分类栏：「今日推荐」，有当期专题时紧跟着专题名（如「期末续命餐」），然后是主食、小吃、饮品、甜品、汤、火锅、烧烤、凉菜。横向可以滑，配菜和其他不单独成栏，选中项靠字重区分。
- 下面是两列菜品方块（`DishTile`），往下滑继续加载。
  - 「今日推荐」是更多推荐；选了分类就是这个分类下的推荐。都受地点和饭点影响。
  - 选了专题：列表顶部是专题介绍和起止时间（「10 月 20 日–10 月 26 日」），下面是专题里的菜，不受饭点影响。列表最底下是「往期专题」。
- 分类栏只影响抽屉里的列表，不影响上面的转盘。
- 列表底部留出导航栏的高度。

**空状态**：当前地点和饭点下一道菜都没有时，舞台换成插画和一句「这附近还没人发过菜，发第一道」，按钮「发布一道菜」。

**地点和饭点面板**

- 底部面板，两组单选：地点（已开放的校区）、饭点（早饭、午饭、晚饭、夜宵），另有「按现在的时间」恢复自动。
- 选完立即刷新转盘和列表，舞台换色。

**往期专题和专题页**

- 往期专题：白底列表，每行是专题名、起止时间和三道菜的小圆图，按时间倒序。
- 专题页：标题是专题名，下面是介绍、起止时间和专题里的菜（两列方块）。从往期专题、菜品详情的专题提示、消息进入。

### 6.5 菜品详情（G-Dish）

- 舞台：封面盘子、分类、菜名、价格。点盘子看大图：先是上传者的照片，接着是评论里的照片，每张标出是谁拍的，左右翻看。
- 右上角：收藏、分享。分享面板里是分享渠道和「复制链接」；看别人的菜时最后多一项「举报」。
- 抽屉从上到下：
  - **店卡**：店名、距离、商圈和楼层，点击进餐厅详情。
  - **专题提示**：收进过专题时，店卡下面一行「收进了本周专题「期末续命餐」」（往期写「收进了专题「……」」），点击进专题页。收进过多个时只显示最近的一个。
  - **两个按钮**：赞（心形加赞数，赞过是按下状态）和「导航去店里」（同 6.6）。
  - **大家怎么说**：这道菜的口味标签，按人数从多到少，最多 6 个，人越多字越大。点一个词就是给这道菜打这个标签，自己打过的再点一次撤回。最后是「＋ 加标签」。一个标签都没有时写「还没人说过，来第一个」。
  - **上传者**：头像、昵称、「10 月 18 日上传」，点击进他人主页；下面是上传者写的说明。看自己的菜时这一栏右边有「编辑」。
  - **吃过的人说**：标题后面跟评论条数。显示最有用的 3 条，下面「看全部 23 条」进全部评论；标题右边「写一条」。一条都没有时写「吃过的话，说两句」。
- **评论的样子**：头像、昵称、时间、文字、照片（最多 3 张小图，点开看大图）、赞（心形加数）、「回复」。有回复时下面露出最早的 2 条，「展开 5 条回复」看全部。每条右边「更多」：自己的是「删除」，别人的是「举报」。
- **全部评论**：白底，顶部切换「最有用」「最新」，底部常驻输入框。
- **写评论**：文字框（最多 200 字）、加照片（最多 3 张），发出后回到菜品详情并滚到这条。回复时输入框里写「回复 小林」，只能写字。
- **加标签面板**：上面是口味词表，多选，自己打过的是选中态；下面是「＋ 自己写」，写的标签进「我的标签」，旁边提示「只有你自己看得见」；最底下一行小字「词表里没有想要的？告诉我们」，进反馈并带上这道菜。
- 未认证或封禁中：点赞、收藏、打标签、评论、关注时弹拦截面板（见 7.3）。
- 编辑页最底下是「删除这道菜」，删除要二次确认。
- 看过的菜记入足迹。
- 菜已经被删除时，显示「这道菜已删除」，可以返回。

### 6.6 餐厅详情（G-Detail）

- 舞台：第一道招牌菜的封面和舞台色；店名、商圈和楼层、「距你 320 m」、菜数（「13 道菜」）、推荐率（「86% 推荐」，下面小字「32 人评过」，规则见 9.7）。
- 右上角：收藏店铺、分享。
- 抽屉从上到下：
  - **导航去店里**：打开手机上的地图 App，装了几个就让用户选，目的地是这家店。Web 上打开网页版地图。
  - **加一道菜**：进入发布第 2 步，店已经选好。
  - **招牌**：获赞最多的 3 道菜，横排，点进菜品详情。不满 3 道时有几道放几道。
  - **大家怎么说**：这家店所有菜的口味标签按人数汇总，最多 6 个。点一个词，下面的全部菜品只看带这个词的菜，再点一次取消。
  - **你觉得这家怎么样**：四个单选胶囊「推荐」「还不错」「一般」「不推荐」。点一个就提交，自己选过的是选中态；可以改选，再点一次已选的撤回。
  - **全部菜品**：两列菜品方块，按赞数排序。
  - 最底下一行小字「信息有误」。
- **信息有误**：选一项（店名不对、位置不对、已关门、和别的店重复、其他），补充说明选填，最多 200 字。提交后提示「已提交，核实后会通过消息通知你」。
- **已关门的店**：舞台下方写「这家店已关门」，「导航去店里」「加一道菜」不可用，其余照常能看。
- 看过的店记入足迹。

### 6.7 附近（G-Nearby）

- 地图当舞台，中心是当前位置，没有定位权限时是校区中心。每家店是一个圆形标记，里面是招牌菜的封面；选中的那家放大、外圈加它的舞台色、下面写店名。
- **搜索**：顶部搜索框「搜店名或菜名」。结果直接落在地图和抽屉里：搜店名，显示名字对得上的店；搜菜名，显示有这道菜的店，行里写「有 酸辣粉 ¥12」。清空搜索回到附近。
- **筛选**：搜索框右边的筛选按钮打开底部面板：
  - 分类：多选，店里有这一类菜就算。
  - 价位：不限、¥15 以下、¥15–30、¥30 以上，单选。
  - 只看推荐率 80% 以上。
  - 只看我收藏的店。
  - 底部「重置」和「看 12 家」，数字随选项实时变化。有筛选时按钮上显示选了几项。
- **商圈**：一排胶囊。点一个，地图移到这个商圈并画出范围，列表只看这个商圈的店；再点一次取消。默认选中当前所在的商圈，不在任何商圈里时不选。
- 右下「回到我的位置」。
- **抽屉**：「附近 18 家」，排序可选「按距离」（默认）、「推荐率最高」「菜最多」。每行是招牌菜缩略图、店名、距离、商圈和楼层、「招牌：鲜虾蟹籽云吞」。
- 点地图标记：选中这家，列表滚到它；再点一次进餐厅详情。点列表行直接进餐厅详情。
- 拖动地图后，按新的地图中心重新加载附近的店。
- 抽屉可以上拉展开、下拉收起。
- 已关门的店不出现。

### 6.8 搜索（G-Search）

- 从发现页右上角进入，白底，自动弹出键盘。
- 搜菜名和店名，结果分「菜」「店」两栏，默认停在「菜」；菜没有结果、店有结果时停在「店」。
  - 菜：两列菜品方块，离你近的在前。
  - 店：和附近抽屉一样的行，离你近的在前，已关门的店排在最后并标明。
- 没输入时显示最近搜过的词，最多 10 个，可以清空。
- 没结果时写「没找到」，认证用户多一个「新建一家店」。

### 6.9 发布一道菜

入口：导航栏右边的「＋」；餐厅详情的「加一道菜」（跳过第 1 步）；发现页空状态的「发布一道菜」；搜索没结果时的「新建一家店」（建好店后直接进第 2 步）。未认证或封禁中点入口时弹拦截面板，不进入流程。

中途关闭时，如果已经填了内容，确认「这道菜还未发布，确定放弃吗？」。不存草稿。

**第 1 步：选店（G-PickShop）**

- 标题「在哪家吃的？」，搜索框「搜店名」。
- 提示「你在万达金街附近，离你近的排在前面」。没有定位时不显示这句，按离校区中心的远近排序。
- 单选列表：招牌菜缩略图、店名、距离、商圈和楼层。已关门的店不出现。
- 底部「没找到？新建一家店」。
- 主按钮「下一步：给袁记云饺加菜」，没选店时不可用。

**新建店**

- 店名：必填，最多 20 个字。
- 位置：必填，地图选点，默认当前位置，拖动地图让中心对准店门口。所属商圈按位置自动判断并显示出来，不用填。
- 地址描述：必填，最多 30 个字，提示「比如 万达金街 1 层」。
- 门头照片：选填，1 张。
- 附近 200 m 内已有同名店时提示「附近已有一家袁记云饺」，可以直接选它，也可以坚持新建。
- 建好后回到第 2 步，店已选好。

**第 2 步：加菜（G-AddDish）**

- 舞台：封面照片和它的舞台色，旁边小字「主色取自照片」。还没加照片时，舞台用汤色，盘子位置是一个虚线圆「加一张照片」。
- 照片条：已加的照片、「＋」再加一张、「1 / 9」。照片可以拍，也可以从相册多选。第一张加好后自动进入调整照片，之后加的照片不用调整。点封面可以重新调整，也可以把别的照片设为封面，换封面后重新调整。
- 照片加进来就开始在后台上传，失败的单张可以重试。
- 抽屉：
  - 「发布到 袁记云饺」和「换一家」。
  - 菜名、价格（见 9.1）。
  - 分类：单选。
  - 适合哪顿：多选，默认勾当前饭点。
  - 标签，可以多选：口味词表加「＋ 自己写」。
  - 说两句：选填，提示「好吃在哪，有什么要注意的」。
- 输完菜名就查重。这家店已有同名菜时，输入框下提示「这家店已有鲜虾蟹籽云吞」和「去看看」，不能发布。点「去看看」进那道菜并打开写评论，已经加的照片带过去。
- 主按钮「发布」。必填项没填完时不可用，按钮上方用 `warn` 写缺哪些必填项，如「请填写价格和分类」。照片没传完时按钮显示进度。
- 发布成功后进入这道菜的菜品详情，提示「发布成功」；从详情返回时回到发起发布的页面。失败时留在本页，内容不丢，说明原因。

**调整照片（G-Crop）**

- 拖动、双指缩放，把主菜放进圆圈里，默认居中。底部的缩放滑条是不能用手势时的替代。
- 「自动去掉背景」开关，默认关。打开后只留下碗盘，效果不好就关掉，退回圆形裁切。开关状态随菜品保存。
- 舞台颜色：三个推荐色，默认第一个，下面实时预览「首页会是这样」。照片太灰时把分类默认色排第一；这时还没选分类就先用汤色，选了分类后自动换成分类默认色，用户手动选过颜色就不再动。
- 「取消」放弃这次调整，「完成」保存裁切和颜色，回到第 2 步。

### 6.10 我的（G-Me）与他人主页

**我的**

- 舞台：我获赞最多的那道菜的封面和舞台色。还没发布过菜时用芒果黄 `stage-mango` 加插画空盘。
- 头像、昵称、用户名（设过才显示）、签名。统计：获赞、上传的菜、粉丝、关注，粉丝和关注可以点进列表。
- 右上角：「编辑资料」和设置。
- 快捷入口：「我的标签」（12 个，用来给菜分类）、「足迹」（最近看过 26 家）。
- 内容分栏：
  - 上传：我发布的菜，两列方块，菜名右边是赞数。
  - 收藏：顶部切换「菜」「店」。菜是两列方块；店是和附近抽屉一样的行。
  - 评论：我写过的评论，每行是菜的缩略图、菜名、我说的话和时间，点进菜品详情并滚到这条。
- 未认证时舞台下方加一条「认证后可以发布和互动」和「去认证」；封禁中显示「账号封禁中，10 月 30 日解封」和原因。

**他人主页**

- 从菜品详情的上传者、评论者、消息、粉丝和关注列表进入。
- 舞台和统计和「我的」一样。右上角是「关注」「已关注」或「回关」，旁边「更多」里是「屏蔽」和「举报」。
- 内容只有「上传」一栏。收藏、评论、标签和足迹是私人的。
- 粉丝、关注列表能不能点开，按对方的隐私设置；不公开时写「对方未公开」。

**粉丝、关注**：头像、昵称、关注按钮，点行进他人主页。

**我的标签**：列出我写过的标签和各自用了几次，可以改名、删除。删除只去掉标签，不影响菜。点一个标签进「标签下的菜」，两列方块。

**足迹**：分「菜」「店」两栏，按最近看过排序，显示看过的时间（「12 分钟前」「周一」）。只有自己看得见，可以清空。

见第 10 节。

### 6.12 设置与编辑资料

**设置**

- 账号与安全：
  - 认证：状态和入口。
  - 用户名：没设过时是「设置用户名」，先验证手机，可以顺便设密码（还没设过密码时）。只能设一次，设好后显示用户名，不能再改。规则见 7.1。设好后这台和其他设备都要重新登录。
  - 手机号：显示时中间四位打码，可以换绑。换绑先用旧手机的验证码或密码确认身份，再验证新手机；新号码已经注册过别的账号时不能换。旧手机不用了、又没设密码的，发邮件给我们处理。
  - 密码：还没设过时是「设置密码」，先验证手机；设过之后是「修改密码」，用旧密码或手机验证码都行。密码 6–64 位。
  - 登录设备：列出登录着的设备和最近使用时间，可以把其他设备下线。
  - 注销账号：见 7.7。
- 隐私：
  - 「公开我的关注列表」「公开我的粉丝列表」两个开关，默认打开。
  - 屏蔽的人：列表，可以解除屏蔽。
  - 「个性化推荐」开关，默认打开。关掉后推荐不再参考你的记录（见第 8 节）。
- 通知：推送开关，见 10.4。
- 关于：隐私政策、用户协议、反馈、版本号。
- 「退出登录」，确认后回到登录页。

**反馈**：文字必填，最多 500 字；截图选填，最多 3 张。从别的页面进来时自动带上相关的菜或店。提交后提示「已提交，处理结果会通过消息通知你」。

**编辑资料**

- 头像（拍照或相册，圆形裁切）、昵称（必填，2–12 个字，可以用中文，不要求唯一）、签名（选填，最多 30 个字）。
- 不出现性别、生日、家乡。
- 封禁中不能改资料。

## 7. 账号、认证与权限

### 7.1 账号与登录

- 「沙软今天吃什么」是同学自己做的产品，和学校没有隶属关系。山大统一认证只用来确认学生身份，不是登录方式。
- 一个手机号对应一个账号。用手机号加验证码登录，新号码第一次登录时自动注册；设了密码后也可以用手机号或用户名加密码登录。
- 账号有**用户名**和**昵称**，注册时都不用填。
  - 用户名是登录用的名字，不能和别人重复，3–10 位字母、数字或下划线，区分大小写。没设时系统内部有一个默认值，但不显示、也不能用来登录；在设置里设一次（见 6.12），设好后不能再改。设过之后在「我的」和账号与安全里显示，可以用来密码登录。
  - 对外展示的是昵称，随时能改，可以用中文，不要求唯一。注册时系统给一个默认昵称，第一次进「我的」时提示改昵称和头像。
- 手机号只用来登录和确认身份，不对外展示。
- 注册后是未认证状态，完成认证（见 6.3）后变成已认证。认证结果跟着账号走，换设备不受影响。
- 校外的人能注册，但没法认证，只能浏览。

### 7.2 权限

| 能做什么 | 未登录 | 未认证 | 封禁中 | 已认证 |
| --- | --- | --- | --- | --- |
| 看推荐、菜品、餐厅、附近、搜索、专题、评论 | — | 能 | 能 | 能 |
| 看他人主页 | — | 能 | 能 | 能 |
| 消息、足迹 | — | 能 | 能 | 能 |
| 设置、反馈、信息有误、举报、屏蔽 | — | 能 | 能 | 能 |
| 退出登录、注销账号 | — | 能 | 能 | 能 |
| 编辑资料 | — | 能 | — | 能 |
| 赞、收藏、打口味标签、写我的标签 | — | — | — | 能 |
| 评论、回复、评价店 | — | — | — | 能 |
| 关注 | — | — | — | 能 |
| 发布菜、新建店、编辑和删除自己的菜 | — | — | — | 能 |

### 7.3 拦截方式

- 按钮照常显示，不隐藏、不置灰，让人知道有这个功能。
- 未认证时点了弹底部面板：「认证后才能点赞」（按动作换词），主按钮「去认证」，次按钮「先逛逛」。
- 封禁中时面板写「账号封禁中，暂时不能点赞」，加上原因和解封时间，没有「去认证」。
- 账号状态在别处变了（比如在网页上完成了认证、刚被封禁），下一次操作时按新状态处理。

### 7.4 登录态

- 登录后一直保持，直到用户退出、长时间没用、改了密码、换绑了手机或设置了用户名。在一台设备上改密码或换绑手机后，其他设备要重新登录；设置用户名后，所有设备都要重新登录。
- 失效时回到登录页，登录后回到原页面。
- 同一账号可以同时在手机和 Web 上登录。
- 退出登录时清掉这台设备上的登录信息和个人数据。

### 7.5 数据存放在境外

账号信息、照片、位置等数据存放在境外服务器。服务端要求的跨站同步同意，由客户端默认替所有用户自动发送，用户看不到这一步。

- 注册、登录和使用中，服务端要求同意时客户端自动同意，登录和使用照常进行。
- 不做同意相关的页面：没有注册时的单独勾选，没有「重新同意」页，设置里没有「数据存放」入口，也没有《数据存放说明》。设计稿里的 `G-RegisterConfirm`、`G-DataNotice`、`G-Reconsent` 不做。
- 数据存在境外、存哪些信息，写进《隐私政策》。

### 7.6 个人信息

- 只收集用得到的：手机号（登录用）、用户名和密码（选设）、认证信息（认证方式、学号、姓名）、昵称、头像、签名、位置、设备信息、使用记录。
- 设备信息（型号、系统版本、设备标识）和使用记录（看了什么、点了什么）用于账号安全、风控、推荐和改进产品，范围见 12.4、12.5。
- 学号和姓名在认证时由学校返回，用来确认一人一号、处理违规，不展示给任何其他用户。
- 位置只在需要时使用，用来算距离、找附近的店和判断商圈；不在后台定位，不记录轨迹。
- 不收集性别、生日、家乡。
- 隐私政策和用户协议在登录页和设置里都能看到。

### 7.7 注销账号

- 入口：设置 → 账号与安全 → 注销账号。
- 注销页说清楚后果：
  - 会删除：资料、认证信息、收藏、我的标签、足迹、评论和回复、关注关系、屏蔽列表；我给别人的赞、口味标签和店铺评价从计数里去掉。
  - 会保留：我上传的菜和新建的店，它们是店铺菜单的一部分；上传者显示「已注销用户」，点了没有反应。
- 确认前要用手机验证码验证身份。
- 申请后有 7 天冷静期，期间账号不能用，重新登录可以撤销注销；7 天后彻底删除。
- 注销完成后，同一个手机号可以注册新账号，用过的统一认证身份和邮箱也可以给新账号认证。

## 8. 推荐

发现页的转盘和「今日推荐」按下面的规则出菜。

- **范围**：当前校区内、没关门的店的菜。
- **饭点**：只出适合当前饭点的菜；不够一批时用不限饭点的菜补齐。
- **质量**：赞多、口味标签多、评论好的菜优先；新发布的菜要有被看到的机会，不能一直被老菜压住。
- **多样**：同一批里同一家店最多 2 道，相邻两道尽量不同分类。
- **不重复**：同一天在转盘上出现过的菜尽量不再出现，除非已经没有别的菜。
- **因人而异**：参考你赞过、收藏过、评价过的菜和店，把你更可能喜欢的往前放；每批至少一半留给大家公认的好菜，避免越推越窄。在设置里关掉「个性化推荐」后不再参考个人记录。
- 你屏蔽的人上传的菜不出现在你的转盘里。
- 未认证账号看到的推荐不带个人因素。

## 9. 内容规则

### 9.1 发布字段

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 店 | 是 | 选已有的店，或新建 |
| 照片 | 是 | 1–9 张，第一张是封面；太大的图先压缩 |
| 封面裁切、舞台色 | 是 | 默认居中、默认第一个推荐色 |
| 菜名 | 是 | 1–12 个字，去掉首尾空格；同一家店不能重名 |
| 价格 | 是 | 0–999 元，最多一位小数，显示时整数不写小数。称重、自选这类不固定的，填一个常吃的价 |
| 分类 | 是 | 10 选 1 |
| 适合哪顿 | 是 | 至少 1 个，默认当前饭点 |
| 口味标签 | 否 | 从词表多选，一次最多 20 个 |
| 我的标签 | 否 | 自己写，每个最多 10 个字 |
| 说两句 | 否 | 最多 300 字 |

### 9.2 查重

- **菜**：同一家店里菜名相同（忽略空格）就算重复，不能发布，引导去已有的那道写评论。两个人同时发布同一道菜时，后发的按重复处理。
- **店**：200 m 内有同名店时提示，用户可以坚持新建。真重复的店由同学通过「信息有误」反馈，运营合并。

### 9.3 照片

- 必须是这道菜的实拍。不能用网图、插画、菜单截图，靠自动检查和举报兜底。
- 封面上舞台和转盘时，用圆形裁切加盘沿（`DishPlate`）。其他照片看大图时原样显示。
- 推荐流的方块直接用封面原图，不套盘沿。
- 评论里的照片同样要是这道菜的实拍，出现在这道菜的大图里，排在上传者的照片后面。

### 9.4 编辑与删除

- 上传者能改自己菜的所有内容，包括换店；改菜名或换店时同样查重。编辑后赞、收藏、口味标签、评论都保留。
- 上传者能删除自己的菜。删除后菜从所有地方消失，评论一起删除，也从别人的收藏和专题里去掉，赞不再计入获赞；相关消息点进去提示「这道菜已删除」。
- 运营能编辑、删除任何菜。运营删掉的菜用系统消息通知上传者，写明原因。

### 9.5 口味标签

- 词表由运营维护，可以增删改，改名后已打的标签跟着改。
- 每人对每道菜的每个词只算一次，可以撤回。
- 「大家怎么说」最多显示 6 个，按人数排序。

### 9.6 我的标签

- 每个最多 10 个字，不能重名。
- 只有自己看得见，可以改名、删除。

### 9.7 店铺评价

- 四档：推荐、还不错、一般、不推荐。只给店，不给菜。
- 认证用户每人对每家店一个评价，可以改选、可以撤回。
- **推荐率** = 选「推荐」和「还不错」的人数 ÷ 评价总人数，四舍五入取整，写「86% 推荐」，下面小字「32 人评过」。
- 评价不满 5 人时不显示推荐率，只写「3 人评过」；没人评过写「还没人评价」。
- 只显示汇总，不公开谁评了哪一档。

### 9.8 评论

- 认证用户才能写。一条评论最多 200 字、最多 3 张照片，文字和照片至少有一样。
- **回复**只有一层：回复别人的回复时写「回复 小林」，仍然挂在同一条评论下面。回复只能写字，最多 200 字。
- **排序**：默认「最有用」，赞多的在前，赞数一样新的在前；可以切到「最新」。菜品详情只露最有用的 3 条。
- **赞**：评论和回复都能被赞，收到的赞计入作者的「获赞」。
- **删除**：作者能删自己的评论和回复，不能编辑。删掉评论时下面的回复一起消失。菜的上传者不能删别人的评论，只能举报。
- 菜被删除时评论一起删除。

### 9.9 专题

- 运营为一个校区挑一组菜（5–20 道），写名字、一句介绍和起止时间。每个校区同一时间最多一个当期专题。
- 当期专题出现在发现页分类栏，过期后进入往期专题。菜品详情里注明这道菜收进过哪个专题。
- 菜被收进专题时，用系统消息通知上传者。
- 专题里的菜被删除后，自动从专题里去掉。

### 9.10 审核、举报与屏蔽

- **自动检查**：发布的照片和文字先过一遍内容检查，明显违规的直接拦下并说明原因，比如「这张照片未通过内容检查，请更换」。
- **举报**：菜、评论和回复、用户都能举报。入口：菜品详情的分享面板、评论的「更多」、他人主页的「更多」。原因：不是这道菜的实拍、广告、违法或不友善、其他，补充说明选填。提交后提示「已提交，我们会尽快处理」。
- **处理**：运营处理举报，结果用系统消息通知举报人；内容被删时通知作者并写明原因。多次违规的账号会被封禁，时长和原因由运营决定，封禁期间能做什么见 7.2。
- **屏蔽**：在他人主页屏蔽一个人后：
  - 他的评论和回复对你隐藏；
  - 他对你的赞、评论、回复、关注不再通知你；
  - 他不能再关注你，已有的关注关系解除；
  - 他上传的菜还在店铺菜单里，但不出现在你的转盘里。
  - 设置 → 隐私 → 屏蔽的人，可以解除屏蔽。

### 9.11 文案

按设计规范「内容与语气」。产品层面再补两条：

- 同一个动作全程同一个叫法：「换一个」「就它了」「加一道菜」「发布」「导航去店里」「写一条」「去认证」。
- 提示和报错用规范短句，说清结果和下一步：「网络连接失败，请重试」，不写「请求失败（40001）」这样的错误码，也不写「网络不太好，再试一次」这样的口语。

## 10. 消息与通知

### 10.1 消息页（G-Inbox）

- 从发现页右上角的铃铛进入，白底。
- 大标题「消息」，旁边「3 条未读」；右上角「全部已读」。
- 分栏：全部、评论、赞和收藏、关注、系统。
- 按「今天」「本周」「更早」分组，组内按时间倒序。
- 每行：未读圆点（7px，读过去掉）、对方头像、一句话、时间，右边是相关菜的缩略图或操作按钮。
- 点一行就算读了，并跳到对应的地方。

### 10.2 消息类型

| 类型 | 例子 | 点击去哪 | 分栏 |
| --- | --- | --- | --- |
| 评论 | 「小林评论了你上传的鲜虾蟹籽云吞：汤很鲜」 | 菜品详情，滚到这条 | 评论 |

### 10.3 规则

- 对自己的内容操作不产生消息。
- 取消赞、取消收藏、撤回标签不产生消息，已经发出的消息不撤回。
- 同一个对象、同一类互动（赞、收藏、口味标签）在同一天的消息合成一条，如「Momo 等 12 人赞了……」，显示最新那个人，时间是最新那次。
- 关注消息里，我还没关注对方时显示「回关」，关注后变成「已互关」。
- 屏蔽的人的互动不产生消息。
- 铃铛的未读圆点在回到 App 前台、回到发现页时刷新。

### 10.4 推送

- 推送和你有关的事：评论、回复、赞和收藏、关注、系统消息。不推饭点提醒，不推营销内容。
- 赞和收藏合并后再推，同一道菜 1 小时内的合成一条：「Momo 等 5 人赞了你上传的番茄牛腩饭」。评论、回复、关注、系统消息一条一推。
- 23:00–08:00 不推送，这段时间的消息只进消息页。
- 设置 → 通知里按类型开关：评论和回复、赞和收藏、关注、系统消息，默认都开。
- 不在第一次打开时要推送权限。第一次发布成功后再问：「有人赞你的菜、评论你的菜时告诉你？」，拒绝后可以在设置里重新打开。
- 点推送直接进对应的页面，和点消息一样。

## 11. 平台与适配

### 11.1 平台差异

Web 版和 App 功能一致，不做简化版。

| | Android、iOS | Web |
| --- | --- | --- |
| 统一认证（只用于认证） | App 内打开学校页面，完成后回到 App | 跳转学校页面再跳回 |
| 定位 | 系统权限 | 浏览器权限 |
| 加照片 | 拍照或相册 | 选文件，手机浏览器可以直接拍 |
| 导航去店里 | 选已安装的地图 App（iOS 包括 Apple 地图） | 打开网页版地图 |
| 分享 | 系统分享面板 | 支持时用系统分享，否则复制链接 |
| 打开分享链接 | 装了 App 打开 App | 打开 Web 版 |
| 推送 | 有 | 没有，只看消息页 |

- Web 支持近两年的 Chrome、Safari、Edge、Firefox，以及微信内置浏览器。
- 在微信里打开分享链接时直接显示 Web 版，顶部一条「在 App 里打开」，点了提示「点右上角，选在浏览器打开」。

### 11.2 屏幕尺寸

设计稿按 390 × 844 画，其他尺寸按下面的规则伸缩。

- **手机宽度（600 以下）**：内容铺满，左右边距保持 `space-20`，中间随宽度伸缩，两列方块等分宽度。窄于 360 时，舞台菜名和价格的字号按宽度缩小，菜名最小 36px，每行仍不超过四个字。
- **宽屏（600 及以上：平板、折叠屏展开、电脑浏览器）**：有舞台的页面（发现、菜品详情、餐厅详情、我的、他人主页）让舞台铺满整个屏幕，抽屉变成左侧的白色悬浮面板（宽 400），菜名、价格、按钮和盘子排在面板右边。面板里的内容单独滚动，舞台不动。发现页的地点、搜索、通知收进面板顶部；转盘沿着屏幕右边缘上下转，下一道从右上角露出来。
- **附近页的宽屏**：同样的排法，地图铺满整个屏幕代替舞台，商圈标签浮在地图上方，列表和地图同时看。
- **宽屏的底部导航**：发现、附近、我的三个页面的导航都放在左侧面板底部，切换时位置不动。
- **宽屏的白底页面**：消息、搜索、设置这类白底页面放在居中的一栏里，最宽 480。
- **高度**：舞台高度随屏幕高度变化，844 高时是 520；矮屏按比例缩小，最矮 420，盘子和转盘跟着缩；高屏最高 560，多出来的高度给抽屉。舞台上的菜名、价格和按钮贴着舞台底部排，保证不被抽屉盖住。
- **方向**：手机只竖屏。平板和电脑浏览器横竖都行，按宽屏规则排。
- **安全区**：避开刘海、灵动岛、屏幕圆角和安卓手势条。顶部栏在状态栏下面，底部导航在 24px 之外再加系统的底部安全区。
- **深色模式**：系统开了深色模式也保持浅色界面。

### 11.3 字号与输入

- 正文、列表、按钮文字跟随系统字号，最大跟到 2 倍；底部导航、胶囊标签这类尺寸固定的控件最大到 1.3 倍；舞台菜名、价格、页面大标题不跟随。
- 字号放大后文字可以换行，不能被截断或互相压住，按钮跟着变高。
- 输入框获得焦点时自动滚到看得见的位置；底部主按钮（下一步、发布、发送）浮在键盘上方。
- 用读屏软件能完整走完主要流程（登录、换菜、看详情、发布），细则见设计规范「无障碍」。

## 12. 运行保障

上线后靠下面这些手段及时修问题、调策略、防滥用。这里写它们在用户那边表现成什么样、能做什么、不能做什么；具体用什么技术实现，写在技术架构和依赖选型文档里。

### 12.1 版本与更新

| 方式 | 什么时候用 | 用户看到什么 |
| --- | --- | --- |
| 热更新 | 修问题、小调整 | 后台下载，下次打开生效，没有提示 |
| 建议更新 | 商店里有新版本 | 发现页弹一次「有新版本」，按钮「去更新」「下次再说」，同一个版本只提示一次 |
| 强制更新 | 版本太旧没法正常用，或者有安全问题 | 打开 App 直接进更新页，只能去更新。尽量少用 |

- 热更新只用于修复问题和不改变功能范围的小改动。新功能、新权限、新的数据收集，都要发新版本、过商店审核。
- 热更新补丁导致打不开时，自动退回上一个能用的版本。
- 新版本和补丁先发给一小部分人（比如 5%），没问题再逐步放到所有人；有问题可以暂停或撤回。
- Web 发布后，下次打开就是新版；正在用的页面提示「有新版本，请刷新页面」，不强制刷新，正在填的内容不丢。
- 设置 → 关于里显示版本号和补丁号，反馈问题时能说清楚。

### 12.2 远程配置与公告

不发版就能调整的内容：

| 类别 | 内容 |
| --- | --- |
| 功能开关 | 发布、新建店、评论、推送、专题、自动去掉背景等，可以单独关闭 |
| 运营参数 | 饭点时间段、推荐每批几道、分类栏顺序、推荐率的显示门槛、风控阈值 |
| 公告 | 普通公告、重要公告 |
| 维护 | 全站只读、停服维护 |
| 版本 | 建议更新、强制更新的版本线 |
| 实验 | A/B 测试的分组（见 12.3） |

- **功能关闭**：入口照常显示，点了提示「该功能暂时关闭」，有原因时写上原因。
- **公告**：普通公告在发现页抽屉顶部占一条，可以关掉，关掉后同一条不再出现；重要公告在打开 App 时弹窗，看过一次不再弹。公告可以按校区、平台、版本分别发。
- **维护**：只读时能看不能发，发布、评论等按钮照常显示，点了提示「系统维护中，暂停发布，预计 23:30 恢复」；停服时打开 App 显示维护页，写明预计恢复时间。
- 配置拉不到时用上次拿到的，从没拿到过就用内置的默认值，不能因为配置失败影响使用。
- 远程配置不能用来：打开新的数据收集或权限、改变隐私政策里承诺的做法、绕过商店审核上线新功能。

### 12.3 A/B 测试

- 用来验证体验上的改动，比如推荐每批几道、转盘按钮的文案、发布页字段的顺序、推送的时机。
- 按账号分组，同一个人在一个实验里始终在同一组，换设备也一样。
- 同一个人同时最多在 3 个实验里，会互相影响的实验不放在同一个人身上。
- 这些不做实验：隐私和权限、协议和同意、举报和屏蔽、安全和风控提示、价格和距离的真实性。任何一组都不能少掉核心功能。
- 每个实验开始前写清楚：验证什么、看哪个指标（见 12.5）、跑多久（一般 1–4 周）、怎样算赢。结束后全量上线或撤掉，不留长期分叉。
- 隐私政策里说明会做这类测试，不单独告诉用户自己在哪一组。

### 12.4 风控

目标是防刷量、防广告和骚扰、保护账号，同时不误伤正常同学。

- **原则**：拦下时说清楚原因和什么时候能恢复，不悄悄失败；觉得被误伤可以通过反馈申诉。下面的数字都是初始值，用远程配置调整。
- **验证码**：同一手机号 60 秒一次、1 小时 5 次、1 天 10 次。每次发验证码前都先过人机验证：判断没有风险时自动通过，用户看不到；有风险时才需要用户手动验证。超限时提示「验证码发送次数已达上限，请明天再试」。
- **登录**：密码连续输错 5 次，这个号 15 分钟内只能用验证码登录。在新设备上登录时，其他设备收到系统消息「你的账号已在新设备上登录」，不是本人可以去设置 → 登录设备把它下线。
- **注册**：同一台设备一天最多注册 3 个账号。
- **频率**：每人每天最多发 20 道菜、建 5 家店、写 100 条评论和回复。操作太快（比如 1 分钟赞 30 次）先提示「操作过于频繁，请稍后再试」，继续就暂时限制。到了上限提示「今日发布已达上限，请明天再试」。
- **内容**：照片和文字先过自动检查（见 9.10）；照片里有二维码、联系方式、广告的拦下；说明和评论里不能放链接和联系方式。
- **刷量**：同一台设备上多个账号的赞、口味标签、店铺评价只算一次；异常集中的赞和评价不计入，涉嫌刷量的账号交给运营处理。
- **自动限制**：轻度违规时自动限制对应的操作一段时间（比如 24 小时不能评论），其他功能照常，提示里写原因和恢复时间。严重或多次违规由运营封禁（见 7.2）。
- 风控要识别设备，这一点写进隐私政策（见 7.6）。

### 12.5 数据与指标

- 统计大家怎么用产品，用来改进体验和判断 A/B 测试的结果。
- **会采集**：看了哪些页面、点了哪些按钮（换一个、就它了、导航去店里、发布等）、停留时长、崩溃和出错、设备型号、系统版本、App 版本。
- **不采集**：输入框里没发出去的内容、相册里没选的照片、通讯录、后台位置。
- 统计数据只用于整体分析和排查问题，不对外提供。

| 指标 | 怎么算 | 为什么看 |
| --- | --- | --- |
| 定下来的人数（核心指标） | 每周点过「就它了」或「导航去店里」的人数 | 直接反映有没有帮人定下来 |
| 换菜次数 | 从打开发现页到「就它了」平均换了几次 | 太多说明推荐不准 |
| 定下来用时 | 从打开发现页到「就它了」的时间 | 越短越好 |
| 内容供给 | 每周新发布的菜和评论数，带照片的评论单独看 | 有没有人在贡献 |
| 内容覆盖 | 有菜的店的占比、每家店平均几道菜 | 内容够不够用 |
| 认证率 | 注册 7 天内完成认证的比例 | 认证引导有没有用 |
| 留存 | 本周用过、下周还来的人的占比 | 长期价值 |
| 健康 | 被举报和被删内容的占比、崩溃率、加载失败率 | 社区和稳定性 |

### 12.6 出问题时

- 推荐拿不到时，转盘先用上一次的那批，提示「网络连接失败，显示的是上次的推荐」。
- 没网时，看过的发现页、菜品详情、我的页可以看缓存；发布、评论等要联网的操作提示没网，填的内容不丢。
- 地图出问题时，附近页退回只有列表。
- 推送出问题不影响消息页。
- 某个功能后端出问题时，先用功能开关把它关掉（见 12.2），其他功能照常。
